# 範囲の規則・分割の採番・逆戻りの提案

`ACPT-7` の操作 (2)（確定にする範囲を確かめた環境に限る）と操作 (4)（期待が成り立たないときの逆戻りの提案）の運用である。
ID 規約は `docs/spec/04-behavior/README.md` の「ID 規約」と (a) を正とする。

## 範囲の規則

- 確定にするのは、確かめた環境に限る。確かめていない環境は別の項目にして「検討中」のまま残す（`ACPT-7` の操作 (2)・ID 規約 (a)）。
- 確定の範囲を決めるのは、ファイル冒頭・行頭の「確定の範囲」の記載・`**確定の記録**` の「環境」欄だけである（[record-format.md](record-format.md)）。ただし、履歴として残した記録と、移管先へ写した記録は、この差分でも後のどの差分でも、確定の範囲を決めず、裏付けにも数えない（下の「履歴として残した記録」）。`**試験の記録**` は範囲を決めない。範囲の外は通さない（確定と読まない）。
- 行頭の確定の範囲がある行は、その範囲の外の環境を確定と読まない。`**確定の記録**` の「環境」が行頭の範囲の外・食い違いのとき、または行頭の範囲の環境に対応する記録が無いときは、確定の範囲を決められないものとして扱う。今回足した・変えた記録なら R4 の照合の対象では通さず、それ以外の旧い記録なら判定を要する（止めて人が解く）。例外は、下の履歴として残した記録だけである（[README.md](README.md) の R4 の範囲の項に従う）。判定を要するのは、上の旧い記録と、R4 の対象外の既存の確定の行（`**確定の記録**` を持たない既存の行の読み。U-11）である。人が旧い記録を解いた結果は、判定票の「範囲の外の旧い記録の判定」の欄に書く（肯定の値は「確認済み」。この判定は範囲を広げず、その記録は裏付けにも範囲にも数えない）。確定の範囲は行頭の範囲に限り、記録の環境が行頭の範囲より広くても広い方に寄せない（ID 規約 (a)・`.claude/rules/spec-reference.md`）。ファイル冒頭の記載と行頭が食い違う場合も同じ。例: 行頭の範囲を Chrome から Chrome と Safari に広げ、記録は Chrome の分だけ足した場合は通さない。
- 履歴として残した記録: 範囲を狭める（分割。例: Chrome と Safari から Chrome へ）差分で、base に同じ形で存在し、この差分で変えていない記録（Safari の分）だけが、行頭の範囲の外でも残ってよい（既存の記録は消さない）。この記録は、判定票の「履歴として残した記録」の欄に書かせ、後の差分でも判定票のその記録で識別する。指定できるのは、範囲を狭める種類の行で、base で範囲の内にあった記録に限る（他の種類の行ではその欄は `-` だけ）。写した記録は、移管・置き換えの行の「写した記録」の欄に必ず列挙させ、後の差分ではその欄と「消える記録の出所」で見分ける（見分けられなければ止める。R1）。履歴として残した記録と、移管先へ写した記録は、この差分でも後のどの差分でも、確定の範囲を決めず、裏付けにも数えない。判定票に無い、行頭の範囲の外の旧い記録は、上のとおり判定を要する。狭めた後の範囲の環境ごとの裏付けは、今回の差分で足した記録で行い（R4 を適用する）、head の行頭に確定の範囲の明示が要る。今回足した・変えた記録の環境が上限の外なら、通さない。履歴の記録または写した記録を持つ行（base でも head でも）で、行頭の範囲を消す、または行頭の範囲を持たない形にする変更は、通さない。履歴の記録・写した記録も、合格でない記録の検査（(ii)・(iii)）からは外さない。旧い記録を変える・消す（行が残る）のも通さない。範囲の分類は [judgment-form.md](judgment-form.md) の「範囲の分類」に従う。
- 記録の「環境」は確定の範囲と一致させる。範囲は、ファイル冒頭と行頭の確定の範囲を上限とし、記録の環境がその外なら、今回足した・変えた記録は通さず、旧い記録は判定を要する（履歴として残した記録だけは例外。上のとおり）。範囲の記載の環境ごとに、今回の記録の裏付けが要る。
- 「確定の範囲」はファイル冒頭の記載だけで済ませず、対象の項目ごとに、その項目の冒頭の「確定の範囲」を原文で確かめる。冒頭に確定の範囲がある項目は、その範囲の外は通さない（`.claude/rules/spec-reference.md` の「確定と検討中」節と同じ趣旨）。
- ファイルが「確定の範囲」を冒頭に書く記載があるときは、全ての確定行の冒頭にそれを付ける（ID 規約 (a)）。
- ラベルの禁止（〔仮想〕〔モック〕〔資料〕の合格を〔実機〕〔人の操作〕の確定に使わない等）の正本は [README.md](README.md) の「原則」である。ここでは写さない。
- 〔人の操作〕の範囲は、記録のある (ブラウザ, authenticator) の組だけである（[record-format.md](record-format.md)）。
- 確定済みの行の範囲を広げる（環境・条件・版・件数を足す）のは確定の行に触れる変更で、段 3 を経る（[README.md](README.md) の「段 3 の対象」）。
- 前の版の結果で代えて確定にしない。組込みの構成に依存する項目は `CG2-4`（`04-behavior/README.md`）の扱いに従う（扱いの細部は利用者の判定待ち）。
- PoC のパラメータの値にすぎないものは、要件の値としては検討中にする（ID 規約 (a)）。

## 分割の採番

確かめていない環境を別の ID に分けるときの採番は、ID 規約に従う。

1. 新しい ID は、そのファイル内の過去最大の番号 +1 を使う。
2. 削除した番号・移管した番号も欠番として数える。再利用しない。移管・置き換えた ID は、各ファイル末尾の「移管・置き換えた ID」の表で確かめる。
3. 最大の番号は、表の行だけでなく、末尾の移管表の ID も含めて原文で確かめてから決める。記憶や要約から決めない（`.claude/rules/spec-reference.md`）。
4. 分けた元の行の確定の範囲と、新しい行の検討中の理由を、互いに ID で引く。分けた残りの検討中の行は、同じ差分に置く（段 3(c) で人が確かめる）。

ID の起こしは人が決める。下書きは自動でよい。

## 逆戻りの提案の様式

期待が成り立たなかったときは、期待を緩めず、次を書いて利用者へ報告する（宛先は利用者。判定は人）。

| 項目 | 書く内容 |
|---|---|
| ID | 対象のビヘイビア ID（複数可） |
| 不成立の段 | [README.md](README.md) の段 0〜6 のどこで成り立たなかったか |
| 環境 | 確かめた環境 |
| 版 | 対象の版（commit の短い sha 等） |
| 期待 | 成り立たなかった期待を ID で引く。値・本文は写さない |
| 失敗基準 | 当たる失敗基準 N-n（spec の「Go/No-Go 判断基準」に当たるものを ID で引く。当たらなければ「なし」） |
| 戻り先のフェーズ | 戻り先の目安（Phase n。決めるのは利用者） |
| 緩めないこと | 期待・成功基準を緩めていないことを明記する |
| 求める判定 | 利用者に求める判定（確定から検討中に戻す・検討中のまま残す・期待の見直し・再試験のどれか。確定のまま残す場合は理由を書かせる） |

### 記入例（架空。確定済みの範囲を戻す提案）

| 項目 | 書く内容 |
|---|---|
| ID | `XMPL-1` |
| 不成立の段 | 段 5 |
| 環境 | 架空の環境 A（確定済みの範囲として、根拠欄に明示されている範囲） |
| 版 | abc1234 |
| 期待 | `XMPL-1` の期待を ID で引く（値・本文は写さない） |
| 失敗基準 | 該当する N-n を引く（無ければ「なし」） |
| 戻り先のフェーズ | 利用者に伺う（目安のみ） |
| 緩めないこと | 期待・成功基準を緩めていない |
| 求める判定 | 環境 A の範囲を確定から検討中に戻すか。戻すか残すかの判定は人（利用者）が行う |

- 期待の変更は提案であって、自動では行わない。spec の変更は spec repo への PR になり、利用者の指示を待つ（`.claude/rules/spec-reference.md`）。
- 秘密値・実機の名前・ホームのパス・内部のアドレスを書かない。
- この repo の PR・Issue・コメントにも、記入済みの判定票・逆戻りの提案の環境の具体を書かない。提案は利用者への報告で渡す。
