# 人の判定の記録の様式

`ACPT-7` の期待（確定への変更の判定は人が記録する）のための **様式** である。書き方は [`docs/security-review/record-form.md`](../security-review/record-form.md) に合わせた。
本様式は AI が作ったものであり、判定ではない。判定・日付・判定者は空欄で渡す。

## 注記: AI の結果を判定欄に入れない

- 判定表の全ての欄には **人だけ** が記入する（結果は根拠欄の値を人が写し、範囲は段 2 で人が決めた値を書く）。AI・自動処理による記入は 0 件にする（`ACPT-7`）。
- 道具の出力・AI のレビューの結果は参考の資料である。判定欄・備考欄に写さない。道具の 0 件は判定ではない（[README.md](README.md)・`.claude/rules/verification.md`）。
- 一人で兼ねるため職務の分離が成り立たない限界は、`D-2026-10-27-5` の (3) からの類推である（書き手の読み。同決定は別の担当についての記録）。同 (3) は、本番の開始の前に担当を見直すとしている（見直すのは利用者）。

## 記入のしかた

- 変更の種類の語彙はこの表が正本である（他の文書は引く）。種類は変更の事実（人が差分から決める。道具は機械で分かるものを照合する）、判定の値は種類ごとの候補から人が書くものとして分ける。道具と人が通すのは肯定の値（太字）だけで、否定・保留・空欄・「指摘あり」は通さない。

| 変更の種類 | 使う場合 | 同じ差分の `**確定の記録**` | 判定の値の候補 |
|---|---|---|---|
| 確定にする | 検討中から確定に変える。最初から確定で足す行も含む。確定のまま前提・操作・期待を変えて同じ範囲で再判定する場合も含む（暫定。[README.md](README.md) の U-13） | 要 | **確定にする**・確定にしない・保留 |
| 範囲を広げる | 確定の行の範囲（環境・条件・版・件数）を広げる。「確定の範囲」の記載（ファイル冒頭・行頭）の削除も含む | 要 | **確定にする**・確定にしない・保留 |
| 範囲を狭める（分割） | 確定の範囲を狭め、残りを検討中の別の行に分ける | 要 | **確認済み**・指摘あり・保留 |
| 確定から検討中に戻す | 確定の行を検討中に戻す | 不要（逆戻りの提案は段 6） | **戻す**・戻さない・保留 |
| 移管 | 確定の行の移管（移管先の確定の行に記録を要する）。移管元が base で確定で、同じ差分で消えて移管表に載り、移管先が前提・操作・期待と範囲を変えずに維持する場合に限る。移管元が検討中、または移管先が内容や範囲を変える場合は「確定にする」（範囲を広げるなら「範囲を広げる」） | 要 | **確認済み**・指摘あり・保留 |
| 削除 | 確定の行の削除 | 不要 | **確認済み**・指摘あり・保留 |
| 置き換え | 行の置き換え（置き換え先が確定の行なら記録を要する）。元が検討中なら「確定にする」 | 要（置き換え先が確定の行のとき） | **確認済み**・指摘あり・保留 |
| 試験の記録の追記 | 確定の行に `**試験の記録**` を足すだけで、ほかを 1 字も変えない | 不要 | **範囲を変えないことを確認**・指摘あり・保留 |
| 文面の変更 | 確定の行の前提・操作・期待以外の文面（優先度・根拠欄の記録以外の文・範囲の語）と、「確定の範囲」の記載の文面の変更。確定の行の前提・操作・期待の変更はこの種類では通さず（誤字の修正を含む。扱いは利用者の判定待ちで、決まるまで）、「確定にする」か「確定から検討中に戻す」に限る | 要 | **確認済み**・指摘あり・保留 |
| 引く先の変更 | 期待・前提・操作・根拠欄で引く ID（期待を委ねた ID など）・`01-brainstorm.md` の既存の `A-`・`D-`（引いているかによらない）・`03-poc/**` の全ファイルの変更、確定の行が引いている ID（接頭辞によらない。`D-`・`A-`・`Q-`・`N-n`・`PoC-`・`QP-`・`TASK-` など）を読み替える・置き換える・答える新規の記述（新しい `D-`・`A-`・`Q-`、番号の無い追記を含む）。引く先の一覧と突き合わせられるまで要確認（判定を要する） | 影響を受ける確定の行ごとに要。判定票は影響を受ける (ID, 範囲) ごとに行を分け、その行の種類を「引く先の変更」とする | **確認済み**・指摘あり・保留 |
| サマリー | 確定の件数が変わる変更、または集計と一致しない状態 | 変更の元の種類に従う | 変更の元の種類に従う |
| 規則の文書の変更 | 確定の定義と読み方を決める文書の変更（判定を要する）。影響を受ける行は、その規則を使う全ての確定の行 | 影響を受ける確定の行ごとに要。判定票は影響を受ける (ID, 範囲) ごとに行を分け、その行の種類を「規則の文書の変更」とする | **確認済み**・指摘あり・保留 |
| 試験の記録への記入 | 確定の行にある `**試験の記録**` の空欄への記入。記入できる欄は件数・結果・記入者と〔人の操作〕の 4 欄（手順・機材の種類・ブラウザの版・実施者）に限る。検討中の行への記入は対象外 | 不要 | **範囲を変えないことを確認**・指摘あり・保留 |
| 既存の記録の変更 | 上の欄以外への記入、`**確定の記録**` への記入・変更・削除、見出しの変更、記入済みの値の変更、既存の `**試験の記録**` の削除・書き換え（行のステータスによらない。検討中の行でも同じ） | 通さない（新しい記録を足し直し、別の種類で判定する） | なし |
| 検討中の行への確定の記録の追加 | ステータスを変えずに足す | 通さない | なし |

- 確定の行の前提・操作・期待の変更が「文面の変更」「移管」「範囲を狭める（分割）」「置き換え」「引く先の変更」と重なるときは、「確定にする」（今回の版の `**確定の記録**` を要する）か「確定から検討中に戻す」を採り、他の種類だけでは通さない。
- 1 つの変更が複数の種類に当たるときは、記録を要する側を採る。例: 期待を委ねられた行の削除は「引く先の変更」として、委ねている側の行に記録を要する。ファイル冒頭・行頭の「確定の範囲」の記載を変えるときは「範囲を広げる」を優先し、「0 行とする理由」を認めない。
- 判定票の列の必須は、種類ごとに次のとおりである。当たらない列は `-` と書き、空欄は通さない。

| 列 | 必須になる場合 |
|---|---|
| ID・変更の種類・判定・判定の日付・判定者 | 全ての種類 |
| 範囲・ラベル・対象の版・根拠欄の記録の参照・結果 | 記録を要する種類 |
| 検討中の理由の解消 | 確定にする場合（U-13 の再判定を除く）、範囲を広げる場合、移管・置き換えで元が検討中の場合 |
| 逆戻りの提案を渡した日付と ID だけ | 確定の行に不合格の `**試験の記録**` を足す場合（試験の記録の追記）、結果が合格以外の記入（試験の記録への記入） |
| 0 行とする理由 | 引く先の変更では、逆引き（ID・接頭辞・節の名前・`〜` の範囲の展開・推移的な参照）が引く確定の行が 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）の場合だけ。1 行でも見つけたら書けず、通さない（見つけた行ごとに行を分ける） |

- 影響を受ける確定の行を探す手順は [README.md](README.md) の段 3(c)（引く先の逆引き）に従う。探した結果は、見つかった行ごとに判定票の行を分けて残す。引く先の変更では逆引きで 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）のときだけ、変更そのものの行に「0 行とする理由」を書け、そのときも人の判定を要する。1 行でも見つけたら、理由では通さない。
- 行でない対象の単位は、次のように書く。ステータスサマリーは `サマリー`・`-`、`D-` の変更はその ID・`-`、`02-poc-plan.md` の変更は節の名前・`-`、「確定の範囲」の記載（ファイル冒頭）はファイル名・`-`。
- 日付は `YYYY-MM-DD` で書く。
- 判定者は利用者または利用者が指名する人（`ACPT-7`）。様式には名前の例を書かない。
- 根拠欄の記録の形式は [record-format.md](record-format.md)、範囲の規則は [scope-rule.md](scope-rule.md) を出典とし、ここでは写さない。
- 値・本文は書かない。ID と参照だけを書く。
- 「根拠欄の記録の参照」は、[record-format.md](record-format.md) の「記録の識別」節の規則で書く（組が重なるときは、根拠を追加した commit と位置まで含める）。参照は 1 件の記録に解決でき、その記録は今回の差分で足されたものでなければならない（base にある旧い記録を指す参照は通さない。[README.md](README.md) の R4）。
- 秘密値・実機の名前・ホームのパス・内部のアドレスを書かない（`.claude/rules/security.md`）。
- 判定者は個人名ではなく役（利用者、または指名の記録への参照）で書く。

### 根拠欄の記録の参照

「根拠欄の記録の参照」は、[record-format.md](record-format.md) の「記録の識別」節の規則で書く。この規則はそこにだけ定義し、ここでは写さない。

## 置き場

- 記入済みの判定票は、この public repo に置かない。spec repo に置き、確定への変更の PR から参照する（[README.md](README.md) の U-8。置き場の path は未定で、利用者の判定待ち）。
- 判定票は、対象の PR のブランチにコミットしない。コミットすると head が変わり、前提の記録の head と一致しなくなる（[README.md](README.md) の R5）。対象の PR のブランチとは別の参照に置き、保存しても検査の対象の head が変わらないようにする（参照の形は未定）。
- この repo には様式だけを置く。
- この repo の PR・Issue・コメントにも、記入済みの判定票・逆戻りの提案の環境の具体を書かない。提案は利用者への報告で渡す。

## 本様式で扱わないこと

- 判定の記入（人が行う）
- spec の修正（利用者の指示を待つ）
