# 人の判定の記録の様式

`ACPT-7` の期待（確定への変更の判定は人が記録する）のための **様式** である。書き方は [`docs/security-review/record-form.md`](../security-review/record-form.md) に合わせた。
本様式は AI が作ったものであり、判定ではない。判定・日付・判定者は空欄で渡す。

## 注記: AI の結果を判定欄に入れない

- 判定表の全ての欄には **人だけ** が記入する（結果は根拠欄の値を人が写し、範囲は段 2 で人が決めた値を書く）。AI・自動処理による記入は 0 件にする（`ACPT-7`）。
- 道具の出力・AI のレビューの結果は参考の資料である。判定欄・備考欄に写さない。道具の 0 件は判定ではない（[README.md](README.md)・`.claude/rules/verification.md`）。
- 一人で兼ねるため職務の分離が成り立たない限界は、`D-2026-10-27-5` の (3) からの類推である（書き手の読み。同決定は別の担当についての記録）。同 (3) は、本番の開始の前に担当を見直すとしている（見直すのは利用者）。

## 記入のしかた

- 変更の種類の語彙はこの表が正本である（他の文書は引く）。種類は変更の事実（人が差分から決める。道具は機械で分かるものを照合する）、判定の値は種類ごとの候補から人が書くものとして分ける。道具と人が通すのは肯定の値（太字）だけで、否定・保留・空欄・「指摘あり」は通さない。

| 変更の種類 | 使う場合 | 同じ差分の `**確定の記録**` | R4 | 判定の値の候補 | ラベル未定のとき |
|---|---|---|---|---|---|
| 確定にする | 検討中から確定に変える。最初から確定で足す行も含む。base で確定の行の前提・操作・期待を変え、範囲の記載を変えずに再判定する場合も含む（暫定。[README.md](README.md) の U-13） | 要 | 適用 | **確定にする**・確定にしない・保留 | 通さない |
| 範囲を広げる | base で確定の行の範囲の分類が「広げる」（下の「範囲の分類」）。「確定の範囲」の記載（ファイル冒頭・行頭）の削除も含む。base に範囲の上限も記録の環境も無い行へ新しい `**確定の記録**` を足す場合も、この種類に固定する | 要 | 適用 | **確定にする**・確定にしない・保留 | 通さない |
| 範囲を狭める（分割） | base で確定の行の範囲の分類が「狭める」。head の行頭に確定の範囲の明示が要る。残りは検討中の別の行に分ける。行頭の範囲の外になる旧い記録は、base で範囲の内にあった記録に限り、判定票の「履歴として残した記録」の欄に書く（選ばれた種類によらず、その行で範囲の分類が「狭める」なら記入できる。下の「記録が消えてよい場合」）| 要 | 適用（狭めた後の範囲の環境ごとに、今回の記録が要る） | **確認済み**・指摘あり・保留 | 通さない |
| 確定から検討中に戻す | base で確定の行が head で検討中。head が確定でないので、前提・操作・期待などほかの変更が重なっても、この種類で通せる（再び確定にするときは「確定にする」） | 不要（逆戻りの提案は段 6） | 対象外（head が確定でない） | **戻す**・戻さない・保留 | 止めない |
| 移管 | base で確定の移管元が、同じ差分で消えて移管表に載り、移管先がこの spec の中の確定の行で、前提・操作・期待と範囲を変えずに維持する場合に限る。移管元が検討中で移管先が確定、または移管先が内容や範囲を変える場合は「確定にする」（範囲を広げるなら「範囲を広げる」）。移管元の記録を移管先へ写す（結果が合格でない・空欄の `**試験の記録**` も、写すことが必須。捨てるのは通さない）。写すときは 1 字も変えない。写した記録は、判定票の「写した記録」の欄に必ず列挙させる。移管先には、移管元の行頭の範囲を同じ字面で持たせる。移管元に行頭の範囲が無く記録の環境で範囲が決まっていたときは、移管先に行頭の範囲を明示させ、それが移管元の記録の環境の和と一致すること（比べられなければ止める。R1） | 要（移管先の確定の行） | 適用 | **確認済み**・指摘あり・保留 | 通さない |
| 移管（検討中） | 移管先の行が head で検討中（移管元が確定でも検討中でも）。同じ差分で移管元が消えて移管表に載る。移管表への追加はこの行に含める。移管先が検討中なので確定の範囲は動かない。写した記録は、移管と同じく必ず「写した記録」の欄に列挙させる（合格でない・空欄の `**試験の記録**` も写すことが必須）。行をまたぐ照合は掛かる。後で移管先を確定にするときは「確定にする」で、写した記録は裏付けに数えない | 不要 | 対象外（確定の範囲が動かない） | **確認済み**・指摘あり・保留 | 止めない |
| spec の外への移管 | base で確定の移管元が、同じ差分で消えて移管表に載り、移管先がこの spec の外（Hub 等）の ID である。head に移管先の行は無い | 不要 | 対象外（head に行が無い） | **確認済み**・指摘あり・保留 | 止めない |
| 削除 | base で確定の行、または合格でない記録・空欄の記録を持つ行（検討中の行を含む。行のステータスによらない）が、head に無く、移管表にも載らない。判定票に旧 ID・base の commit・消える記録の出所を残す | 不要 | 対象外（head に行が無い） | **確認済み**・指摘あり・保留 | 止めない |
| 置き換え | 行の置き換え（置き換え先が確定の行なら記録を要する）。元が検討中で置き換え先が確定なら「確定にする」。置き換え先にも、移管と同じ行頭の範囲の要件（置き換え元の行頭の範囲を同じ字面で持たせる。元に行頭の範囲が無ければ、元の記録の環境の和を明示。比べられなければ止める。R1）を課す。置き換え元の単位（base で確定で、head に行が無く、置き換え表に載る）の種類も「置き換え」（記録は不要。記録を要するのは置き換え先の行の単位）。移管元の `**試験の記録**` と同じく、元の結果が合格でない・空欄の `**試験の記録**` は、置き換え先へ写すことが必須（捨てるのは通さない）| 要（置き換え先が確定の行のとき） | 適用（同左） | **確認済み**・指摘あり・保留 | 通さない（置き換え先が確定の行のとき） |
| 試験の記録の追記 | 確定の行に `**試験の記録**` を足す。ほかに記録を要する種類の変更が無い | 不要 | 対象外（ほかの変更が無いときだけ） | **範囲を変えないことを確認**・指摘あり・保留 | 止めない |
| 試験の記録への記入 | 確定の行にある `**試験の記録**` の空欄への記入。記入できる欄は件数・結果・記入者と〔人の操作〕の 4 欄（手順・機材の種類・ブラウザの版・実施者）に限る。検討中の行への記入は対象外。ほかに記録を要する種類の変更が無い | 不要 | 対象外（ほかの変更が無いときだけ） | **範囲を変えないことを確認**・指摘あり・保留 | 止めない |
| 移管表の修正 | 行のステータス・範囲・本文を変えず、移管表に載っている ID を消さずに、移管先の ID・備考などの記載だけを直す。直した ID を引く確定の行が逆引きで 1 行でもあれば、その行に「引く先の変更」を当てる（記録を要しない扱いは、逆引きで 0 行のときだけ） | 不要 | 対象外（ほかの変更が無いときだけ） | **確認済み**・指摘あり・保留 | 止めない |
| 文面の変更 | 確定の行の前提・操作・期待以外の文面（優先度・根拠欄の記録以外の文・範囲の語）と、「確定の範囲」の記載の文面の変更。確定の行の前提・操作・期待の変更はこの種類では通さず（誤字の修正を含む。扱いは利用者の判定待ちで、決まるまで）、「確定にする」か「確定から検討中に戻す」に限る | 要 | 適用 | **確認済み**・指摘あり・保留 | 通さない |
| 引く先の変更 | 期待・前提・操作・根拠欄で引く ID（期待を委ねた ID など）・`01-brainstorm.md` の既存の `A-`・`D-`（引いているかによらない）・`03-poc/**` の全ファイルの変更、確定の行が引いている ID（接頭辞によらない。`D-`・`A-`・`Q-`・`N-n`・`PoC-`・`QP-`・`TASK-` など）を読み替える・置き換える・答える新規の記述（新しい `D-`・`A-`・`Q-`、番号の無い追記を含む）。影響を受けた確定の行の再判定の種類である。引く先の一覧と突き合わせられるまで要確認（判定を要する） | 影響を受ける確定の行ごとに要（今回の版。再確定なので、肯定の値も「確定にする」と同じ） | 適用（「0 行とする理由」の行は、照合する確定の行もラベルも無いので、R4 とラベル照合の対象外。理由と人の判定が必須） | **確定にする**（影響を受けた行の再判定。利用者の判定 (1) に揃えた補足で、利用者の確認待ち）・確定にしない・保留。「0 行とする理由」の行は再判定する行が無いので **確認済み**・指摘あり・保留（利用者の判定 2026-11-21） | 通さない（「0 行とする理由」の行は止めない） |
| 規則の文書の変更 | 確定の定義と読み方を決める文書の変更（判定を要する）。影響を受ける行は、その規則を使う全ての確定の行 | 影響を受ける確定の行ごとに要（再確定。引く先の変更と同じ） | 適用（「0 行とする理由」の行は、照合する確定の行もラベルも無いので、R4 とラベル照合の対象外。理由と人の判定が必須） | **確定にする**（影響を受けた行の再判定。利用者の判定 2026-11-21）・確定にしない・保留。「0 行とする理由」の行は **確認済み**・指摘あり・保留（利用者の判定 2026-11-21） | 通さない（「0 行とする理由」の行は止めない） |
| サマリー | 確定の件数が変わる変更、または集計と一致しない状態 | 変更の元の種類に従う | 同左 | 変更の元の種類に従う | 同左 |
| 既存の記録の変更 | 行が head に残るのに、上の欄以外への記入、`**確定の記録**` への記入・変更・削除、見出しの変更、記入済みの値の変更、既存の `**試験の記録**` の削除・書き換え（行のステータスによらない。検討中の行でも同じ） | 通さない（新しい記録を足し直し、別の種類で判定する） | - | なし | - |
| 検討中の行への確定の記録の追加 | ステータスを変えずに足す | 通さない | - | なし | - |
| 欠番の ID の復活 | 新しく足す ID の番号が、base の時点のそのファイルの同じ接頭辞の最大の番号以下（欠番の再利用）、または base の移管表に載る ID を行として足す。道具が番号で機械的に見分ける（ID 規約。新規はファイル内の最大 +1、欠番は再利用しない。利用者の判定 2026-11-21）。base の最大 +1 から連続して足す番号（+1, +2, …）は新しい ID で、欠番の復活ではない | 通さない | - | なし | - |
| 番号の飛ばし | 新しく足す ID の番号が、base の時点のそのファイルの同じ接頭辞の最大の番号（移管表の ID を含む）+1 から連続していない（飛ばした）。ID 規約から外れるので、判定を要する。新しい行自体の種類（確定にする等）の行に加えて、この行を別に 1 行置く（この行は追加の確認で、新しい行の記録の要否は、その行自体の種類に従う） | 不要 | 対象外 | **確認済み**・指摘あり・保留 | 止めない |

### 種類の決め方

- 最初に、「通さない」種類（欠番の ID の復活・移管表から ID を消す変更・既存の記録の変更・検討中の行への確定の記録の追加）に当たるかを判定する。当たれば、他の種類を見ずに通さない（欠番の ID を確定の行として足す変更も、「確定にする」とは読まない。[README.md](README.md) の R6 も同じ）。
- 判定票の (ID, 範囲) の単位ごとに、上の表の種類がちょうど 1 つ当たる（「番号の飛ばし」の行は、新しい行自体の種類の行に加えて別に置く）。ただし、記録を要しない種類（試験の記録の追記・試験の記録への記入・移管表の修正）だけが同じ行に重なるときは、種類ごとに判定票の行を分ける（下の項）。段 3 の対象は全て、表のどれかの種類に当たる（当たらないものは判別できないので止める。R1）。
- base で確定でない行（検討中の行）の削除は、その行に合格でない記録・空欄の記録が無ければ段 3 の対象でないので、種類が無く、判定票の行も要らない。合格でない記録・空欄の記録があれば、種類「削除」の行を要する（旧 ID・base の commit・消える記録の出所を残す。行のステータスによらない）。検討中の行の移管は、移管表への追加が段 3 の対象なので、種類「移管（検討中）」（または移管先が確定なら「確定にする」）の行を要する。行をまたぐ照合は、行のステータスによらず掛かる（合格でない記録・空欄の記録がある行を消し、同じ差分で別の行を確定にする等があれば通さない）。
- 先に head の状態で分ける。head の行が確定でない、または行が無いときは、「確定から検討中に戻す」「削除」「spec の外への移管」「移管」（移管元の単位。記録を要するのは移管先の行の単位）「移管（検討中）」「置き換え」（置き換え元の単位。同様）のどれかで、ほかの変更が重なっても同じ種類である（R4 の対象外）。ただし、行が head に残るときの既存の `**確定の記録**`・`**試験の記録**` の削除・書き換えは含めず、通さない（上の「既存の記録の変更」）。
- head の行が確定のときは、肯定の値が「確定にする」の種類を先に採る。順序は 範囲を広げる＞確定にする＞引く先の変更＞規則の文書の変更＞範囲を狭める（分割）＞移管＞置き換え＞文面の変更＞（記録を要しない 3 種）。複数当たるときは、この順で先に当たる種類の行にする。後ろの種類の条件（記録・確かめる項目）も満たす。範囲の分類が「狭める」の行では、選ばれた種類によらず、狭める行の条件（head の行頭の範囲の明示・狭めた後の環境ごとの今回の記録・履歴欄の記入）を満たす。
- 記録を要しない 3 種（試験の記録の追記・試験の記録への記入・移管表の修正）は、その行に記録を要する種類の変更が 1 つも無いときだけ当たり、R4 の対象外である。同じ行に記録を要しない種類だけが重なるときは、種類ごとに判定票の行を分ける。記録を要する種類の変更が 1 つでも重なれば、その種類が当たり、R4 を適用する。
- 確定の行の前提・操作・期待の変更が「文面の変更」「移管」「範囲を狭める（分割）」「置き換え」と重なるときは、「確定にする」か「確定から検討中に戻す」を採り、他の種類だけでは通さない。範囲の拡大が重なるときは「範囲を広げる」（優先順位）で、どちらも、変更後の期待に対する今回の版の合格の `**確定の記録**` を要する。
- 例: 期待を委ねられた行の削除は、削除の行のほかに、委ねている側の確定の行に「引く先の変更」の行を要する。ファイル冒頭・行頭の「確定の範囲」の記載を変えるときは、範囲の分類に従い、広げるなら「範囲を広げる」で、「0 行とする理由」を認めない。

### 範囲の分類

base で確定の行について、base の範囲と head の範囲を比べる。base の範囲は、base の行頭の確定の範囲（無ければ、base の `**確定の記録**` の環境の全て。履歴の記録と写した記録は除く。除いた結果、行頭も記録も無い行は、比べられないものとして止める。R1）。head の範囲は、head の行頭の確定の範囲。

| 比べた結果 | 種類 |
|---|---|
| head が base の真に小さい部分集合（base に無い環境が 1 つも無い） | 範囲を狭める（分割）。head の行頭に明示の範囲が要る |
| head に base に無い環境が 1 つでもある（入れ替えなど、狭める側と広げる側の両方に当たる場合を含む） | 範囲を広げる |
| 同じ | 範囲の変更なし（文面の変更・確定にする等、ほかの変更の種類に従う） |
| 比べられない（base に範囲の上限も記録の環境も無い・環境の表記が対応づけられない等） | 新しい `**確定の記録**` を足すなら「範囲を広げる」に固定。判別できなければ止める（R1） |

### 記録が消えてよい場合

- 消えてよいのは、行（ID）ごと head から消える場合（削除・移管・置き換え元・spec の外への移管）だけである。同じ差分で同じ ID の行を足し直すなら、行が残るので削除と見なさず、既存の記録の変更として通さない。
- 移管・置き換えでは、移管元・置き換え元の `**試験の記録**` のうち、結果が合格でないもの・空欄のものを、移管先・置き換え先へ写さずに捨てることは通さない（写すことが必須）。写すときは 1 字も変えない。変える・一部を変えるのは通さない。
- 移管先へ写した記録と、履歴として残した記録は、この差分でも後のどの差分でも、確定の範囲を決めず、裏付けにも数えず、R4 の「今回足した記録」にも数えない。履歴の記録・写した記録も、合格でない記録の検査（(ii)・(iii)）からは外さない。写した記録を受け取る全ての行（移管・移管（検討中）・置き換え先）の「写した記録」の欄は必須で、後の差分ではこの欄と「消える記録の出所」で写した記録を見分ける。見分けられなければ止める（R1）。
- 同じ差分で消える行（削除・spec の外への移管・移管元・置き換え元を含む。確定の行でも検討中の行でも同じ）の base に、合格でない記録か結果欄が空欄の記録が 1 件でもあり、かつ同じ差分で別の行（移管先・置き換え先を除く。それらは同じ版の照合〔[README.md](README.md) の R4 の (iii) の移管元の句〕に任せる）を確定にする・確定の記録を足す・範囲を広げる変更があれば、通さない（同じ中身を別 ID で足し直す経路を塞ぐ。行が同じ中身かは道具が判定できないので、一律に止める）。消す差分と確定にする差分を分けた場合は、消す差分の判定票に種類「削除」の行（旧 ID・base の commit・消える記録の出所。検討中の行でも同じ）を残させる。後続の確定にする差分の段 3(c) では、同じファイルで削除済みの旧 ID の判定票を探し、期待の比較の結果を判定票の「削除済みの旧 ID との比較」の欄に残させる（[README.md](README.md) の道具の限界）。
- 行が head に残るなら、既存の記録の削除・書き換えは通さない（上の「既存の記録の変更」）。
- 範囲を狭めたとき、行頭の範囲の外になる旧い確定の記録は、base に同じ形で存在し、この差分で変えていない場合に限り、履歴として残してよい。判定票の「履歴として残した記録」の欄に、どの記録が履歴かを書き、後の差分でもこの判定票の記録で識別する。記入できるのは、選ばれた種類によらず、その行で範囲の分類が「狭める」ときだけ（base で範囲の内にあった記録に限る。分類が「狭める」でない行は `-` だけ）。履歴の記録は確定の範囲を決めない（確定の範囲を広い側に寄せない。[scope-rule.md](scope-rule.md)）。判定票に無い、行頭の範囲の外の旧い記録は、判定を要する（止めて人が解く）。その結果は、判定票の「範囲の外の旧い記録の判定」の欄に書く（記録の参照・判定の値・根拠）。この判定は範囲を広げず、その記録は裏付けにも範囲にも数えず、(ii)・(iii) からも外さず、「範囲が重ならないとした根拠」の代わりにもならない。履歴の記録または写した記録を持つ行（base でも head でも）で、行頭の範囲を消す、または行頭の範囲を持たない形にする変更は、通さない。
- 消える記録は、base の commit で引ける。判定票の行に「消える記録の出所」（base の commit と元の ID。移管元・置き換え元の単位も同じ）を残す。
- 判定票の列の必須は、種類ごとに次のとおりである。当たらない列は `-` と書き、空欄は通さない。

| 列 | 必須になる場合 |
|---|---|
| ID・変更の種類・判定・判定の日付・判定者 | 全ての種類 |
| 範囲・ラベル・対象の版・根拠欄の記録の参照・結果 | 記録を要する種類 |
| 検討中の理由の解消 | 確定にする場合（U-13 の再判定を除く）、範囲を広げる場合、移管・置き換えで元が検討中の場合 |
| 逆戻りの提案を渡した日付と ID だけ | 確定の行に不合格の `**試験の記録**` を足す場合（試験の記録の追記）、結果が合格以外の記入（試験の記録への記入） |
| 対応する引く先・規則の文書の変更 | 引く先の変更・規則の文書の変更の影響を受ける行（種類によらない）と、0 行とする理由の行。変更した ID・`D-`・`A-`・ファイルの path・`03-poc` のファイル・規則の文書の節を書く |
| 範囲が重ならないとした根拠 | 同じ ID・同じ版で範囲の書き方が違う合格でない記録を、人が「重ならない」と判定したとき（範囲の対応を書く）。判定の根拠なしに通さない |
| 履歴として残した記録 | 範囲の分類が「狭める」の行の、base で範囲の内にあった記録のうち行頭の範囲の外になる旧い記録（どの記録かを識別できるように書く）。選ばれた種類によらず、その行で範囲の分類が「狭める」ときに記入できる（base で範囲の内にあった記録に限る。分類が「狭める」でない行は `-` だけ） |
| 写した記録 | 写した記録を受け取る全ての行（移管・移管（検討中）・置き換え先）で、写した記録を必ず列挙する（後の差分で見分ける）。それ以外の行は `-` だけ |
| 範囲の外の旧い記録の判定 | 行頭の範囲の外・食い違いの旧い記録（判定票の履歴の欄に無いもの）を人が解いたとき、その記録の参照・判定の値（肯定の値は **確認済み**・指摘あり・保留）・根拠。この判定は範囲を広げず、その記録は裏付けにも範囲にも数えず、合格でない記録の検査（(ii)・(iii)）からも外さず、「範囲が重ならないとした根拠」の代わりにもならない。無ければ `-` |
| 削除済みの旧 ID との比較 | 確定にする・範囲を広げる行で、同じファイルで削除済みの旧 ID の判定票（種類「削除」）を探した結果。見つかった旧 ID ごとに、期待の比較の結果（同じ中身の足し直しでないこと）を書く。0 件なら「0 件」と書く |
| 消える記録の出所 | 削除・移管・spec の外への移管・置き換え（元の単位を含む）で、行とともに消える記録がある場合（base の commit と元の ID） |
| 0 行とする理由 | 引く先の変更では、逆引き（ID・接頭辞・節の名前・`〜` の範囲の展開・推移的な参照）が引く確定の行が 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）の場合だけ。1 行でも見つけたら書けず、通さない（見つけた行ごとに行を分ける） |

- 影響を受ける確定の行を探す手順は [README.md](README.md) の段 3(c)（引く先の逆引き）に従う。探した結果は、見つかった行ごとに判定票の行を分けて残す。引く先の変更では逆引きで 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）のときだけ、変更そのものの行に「0 行とする理由」を書け、そのときも人の判定を要する。1 行でも見つけたら、理由では通さない。
- 行でない対象の単位は、次のように書く。ステータスサマリーは `サマリー`・`-`、`D-` の変更はその ID・`-`、`02-poc-plan.md` の変更は節の名前・`-`、「確定の範囲」の記載（ファイル冒頭）はファイル名・`-`。
- 日付は `YYYY-MM-DD` で書く。
- 判定者は利用者または利用者が指名する人（`ACPT-7`）。様式には名前の例を書かない。
- 根拠欄の記録の形式は [record-format.md](record-format.md)、範囲の規則は [scope-rule.md](scope-rule.md) を出典とし、ここでは写さない。
- 値・本文は書かない。ID と参照だけを書く。
- 「根拠欄の記録の参照」は、[record-format.md](record-format.md) の「記録の識別」節の組で 1 件に解決できるように書く（組が重なるときは、根拠を追加した commit と位置で補う）。参照は 1 件の記録に解決でき、その記録は今回の差分で足されたものでなければならない（base にある旧い記録を指す参照は通さない。[README.md](README.md) の R4）。
- 秘密値・実機の名前・ホームのパス・内部のアドレスを書かない（`.claude/rules/security.md`）。
- 判定者は個人名ではなく役（利用者、または指名の記録への参照）で書く。

## 置き場

- 記入済みの判定票は、この public repo に置かない。spec repo に置き、確定への変更の PR から参照する（[README.md](README.md) の U-8。置き場の path は未定で、利用者の判定待ち）。
- 判定票は、対象の PR のブランチにコミットしない。コミットすると head が変わり、前提の記録の head と一致しなくなる（[README.md](README.md) の R5）。対象の PR のブランチとは別の参照に置き、保存しても検査の対象の head が変わらないようにする（参照の形は未定）。
- この repo には様式だけを置く。
- この repo の PR・Issue・コメントにも、記入済みの判定票・逆戻りの提案の環境の具体を書かない。提案は利用者への報告で渡す。

## 本様式で扱わないこと

- spec の修正（利用者の指示を待つ）
