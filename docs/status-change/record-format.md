# 根拠欄の記録の形式

`ACPT-7` の操作 (1)（試験の記録を根拠欄に追記する）の書式である。書式は暫定で、spec 側での採用は利用者の判定待ち（[README.md](README.md) の U-1）。
例の ID は架空の `XMPL-1` で、実在の ID ではない。

## 形式

根拠欄の末尾に、次の 1 行を `<br>` で続けて追記する。

```
<br>**確定の記録**: 日付=YYYY-MM-DD ; ラベル=〔…〕 ; 環境=… ; 対象の版=… ; 出典=… ; 出力=… ; 件数=n/m ; 結果=合格 ; 記入者=… ; 判定者=… [ ; 手順=… ; 機材の種類=… ; ブラウザの版=… ; 実施者=… ] [ ; 判定の記録=… ]
```

角括弧の欄は任意の位置を示す（括弧自体は書かない）。〔人の操作〕の記録では、手順・機材の種類・ブラウザの版・実施者を (2) 以降で必須にする。

ステータスを変えない追記（試験をしたが確定にしない）は、見出しを `**試験の記録**` にして同じ形で書く。`**確定の記録**` は、`ACPT-7` の操作 (1) の「試験の記録」のうち、同じ差分に記録を要する種類で足すものである（記録の要否は [judgment-form.md](judgment-form.md) の表に従う）。

- `**確定の記録**` の見出しと判定者の値は、記録を要する種類の変更（[judgment-form.md](judgment-form.md) の表に従う）で、判定した本人（人）が書く。
- 自動の収集・AI の下書きは `**試験の記録**` だけを書く。判定者の欄は空（未判定）にする。検討中の行の `**試験の記録**` は、人が判定したら埋める。確定の行の `**試験の記録**` では、判定者の欄は空のままとする（確定の行か検討中の行かは、base の状態で見る。同じ差分でステータスを変える行は確定の行として扱う。判定者の欄への記入は通さない。[README.md](README.md) の段 3 の対象の「既存の記録の変更」）。確定の記録では判定者は必須である。
- `**試験の記録**` の結果欄: 自動・AI は結果欄を書かず、別の欄 `出力=`（終了コードと件数）だけを書く。結果欄（5 値）は人が書く。人が書く前の結果欄と件数欄は空（未記入）にしてよい。〔資料〕〔人の操作〕の試験の記録は自動では作らない。結果を確定の根拠にするかの判断も人が書く。
- 結果欄は記録の値で、確定にするかの判定とは別である。判定は [judgment-form.md](judgment-form.md) の「判定」欄に人が書く（同様式の「結果（記録の値）」と「判定」の区別を引く）。
- 判定者は個人名ではなく役で書く（利用者、または指名の記録への参照）。

記録は 3 つの時点に分ける。必須の欄は時点で変わる。

| 時点 | 書く人 | 必須の欄 |
|---|---|---|
| (1) 判定前の `**試験の記録**`（自動の収集） | 自動でよい | 日付・ラベル・環境・対象の版・出典・出力。件数・結果・記入者・判定者は空にする（自動・AI は書かない。`件数= ; 結果= ; 記入者= ; 判定者=`）。機械が出した件数・終了コードは `出力=` に残す |
| (2) 人が結果を記入した `**試験の記録**` | 人 | (1) に加えて、件数・結果（5 値のどれか）・記入者。〔人の操作〕の記録は、さらに手順・機材の種類・ブラウザの版・実施者。判定者は空（未判定）のままでよい。結果が `未実施`・`実行できない` のときの日付・件数は下の欄の表に従う |
| (3) `**確定の記録**` | 人 | 日付・ラベル・環境・対象の版・出典・出力・件数・結果・記入者・判定者の全て。〔人の操作〕の記録は、さらに手順・機材の種類・ブラウザの版・実施者 |

| 欄 | 必須の時点 | 内容 |
|---|---|---|
| 日付 | 全て | 試験をした日（`YYYY-MM-DD`）。結果が `未実施`・`実行できない` のときは、記録した日（実行を試みた日があればその日） |
| ラベル | 全て | 検証の種類。下の 5 種から選ぶ |
| 環境 | 全て | 確かめた環境。`**試験の記録**` は確定の範囲を決めない。範囲を決めるのは、ファイル冒頭と行頭の「確定の範囲」の記載・`**確定の記録**` だけで、確定にする範囲はこの環境に限る（[scope-rule.md](scope-rule.md)）。差分に新しい `**確定の記録**` があれば、変更の種類は、記録を要する種類（[judgment-form.md](judgment-form.md) の表に従う）に限る。範囲の分類（同 judgment-form の「範囲の分類」が正本）に従い、「広げる」、または比べられないとき（base に範囲の上限も記録の環境も無い等）は、新しい `**確定の記録**` を足すなら種類を「範囲を広げる」に固定する。判別できなければ止める（[README.md](README.md) の R1）。<br>確定のまま前提・操作・期待を変えて同じ範囲で再判定する場合も、今回の版の `**確定の記録**` を足し、種類は「確定にする」とする（暫定。専用の種類を設けるかは利用者の判定待ち。[README.md](README.md) の U-13）。範囲の拡大が重なるときは「範囲を広げる」で、変更後の期待に対する今回の版の記録を要する。結果が `未実施`・`実行できない` のときは、試す予定だった環境または試行した環境を `環境=予定:…` と書き、特定できなければ `環境=-` と書く。どちらも確定の範囲の根拠にならない |
| 対象の版 | 全て | 試験した対象の版（commit の短い sha 等） |
| 件数 | (2)・(3) | `n/m`（合格 n・対象 m。m の定義は「結果の値」の節）。人が合格件数を確かめた段階で埋める。(1) では空でよい。結果が `未実施`・`実行できない` のときは、対象数 m が分かる場合は `件数=-/m`、分からない場合は `件数=-/-` と書く（合格件数は実行していないので `-`） |
| 出典 | 全て | 試験の出典（PoC-n・QP-n・ACPT-n・TASK-n・試験名）。時点 (1) から必須で、全てのラベルに求める |
| 出力 | 全て | 試験の道具の機械の出力のうち、終了コードと件数だけを書く（例: `終了コード 0・ok=3`）。5 値の語（合格・不合格・判定不能・実行できない・未実施）は書かない。機械の出力が得られた場合は必須（自動の収集・人の記入のどちらでも）。得られなかった場合は `出力=なし` と書く。判定前の件数はここに残す |
| 結果 | (2)・(3) | `合格`・`不合格`・`判定不能`・`実行できない`・`未実施` のどれか 1 つ。人が書く。(1) では空でよい |
| 記入者 | (2)・(3) | この記録を書いた人の役（利用者、または指名の記録への参照）。名前・個体の識別子は書かない。(1) では空 |
| 判定者 | (3) | 判定した人の役（利用者、または指名の記録への参照）。AI・自動処理を書かない。(1)(2) では空（未判定）。検討中の行では人が判定したら埋め、確定の行の `**試験の記録**` では空のままとする（確定の行か検討中の行かは、base の状態で見る。同じ差分でステータスを変える行は確定の行として扱う） |
| 手順 | 〔人の操作〕の (2)・(3) で必須 | 手順の出典（ID・PoC の手順の番号）。`手順=` |
| 機材の種類 | 〔人の操作〕の (2)・(3) で必須 | 使った authenticator の種類（個体の名前・識別子は書かない）。`機材の種類=` |
| ブラウザの版 | 〔人の操作〕の (2)・(3) で必須 | 使ったブラウザの版（`ACPT-8` の記録項目）。`ブラウザの版=` |
| 実施者 | 〔人の操作〕の (2)・(3) で必須 | 操作した人の役（`ACPT-8` の記録項目。名前は書かない）。`実施者=` |
| 判定の記録 | 任意 | 人の判定の記録への参照（[judgment-form.md](judgment-form.md)） |

件数欄も結果欄と同じく、自動・AI は書かない（機械の件数は `出力=` に残す）。
`**確定の記録**` の結果は `合格` に限る。合格以外なら確定の記録にせず、`**試験の記録**` として残す（逆戻りの提案は [scope-rule.md](scope-rule.md)）。ただし、同じ差分で同じ (ID, 範囲, 版) の確定の記録を足すとき、合格でない `**試験の記録**` が 1 件でもあれば通さない（合格の記録で打ち消さない。[README.md](README.md) の R4 の照合）。数える対象は、(i) 差分で足した・変えた全ての `**確定の記録**`、(ii) head にある同じ (ID, 範囲, 版) の全ての `**試験の記録**`（今回足したもの・今回空欄に記入したもの・変えていないもの。head で結果欄が空欄のものも合格でないものとして数え、未完の試験が残っていれば確定にしない）、(iii) base にある同じ (ID, 範囲, 版) の合格でない記録（base で結果欄が空欄だった記録は base では数えず、今回記入した値を (ii) で見る。移管・置き換えでは、移管表で対応づけた移管元の ID の base の記録も含める）である。結果が `合格` でも、件数欄が空欄・`n/m` の形でない記録は、合格でないものとして数える。同じ ID・同じ版で範囲の書き方が違う合格でない記録は、範囲の書き方によらず判定を要する（重なるかは人が判定し、重なるなら通さず、判別できなければ止める。「重ならない」と判定したら、その根拠を判定票の「範囲が重ならないとした根拠」に残す）。
結果欄に値を書くのは人だけで、書いた時点で (2) になる。値を書いた後は 5 値のどれかでなければならない（空欄に戻さない）。
確定の行にある `**試験の記録**` への記入の扱いは、[README.md](README.md) の段 3 の対象の「既存の記録の変更」に従う（判定を要する／通さない）。

### 結果の値

- 値は `02-poc-plan.md` の「記録の形」節の 4 値（合格・不合格・判定不能・実行できない）に合わせる。`未実施` は、実施できなかった項目を合格に数えず記録するための値で、書き手の補足である（関連: `ACPT-8`）。
- 合格以外は合格に数えない（`ACPT-8`）。
- 結果は対象の ID の期待・成功基準で決め、件数の多寡では決めない。`件数=n/m` で n<m なら合格にしない。n>m は形式の不整合で、記録として認めない（`結果=合格` も認めない）。m=0（`0/0`）も認めない（m≥1）。m は対象の ID の期待・成功基準が数える対象の数で、成功基準が「少なくとも一方」のように数える場合は、その単位で n/m を書く。

### 書き方の制約

- 欄の区切りは ` ; `（空白・セミコロン・空白）。
- 値に `|`・`;`・`<br>` を含めない（表の列・欄・追記の区切りと衝突するため）。
- 秘密値・実機の名前・ホームのパス・内部のアドレスを書かない（`.claude/rules/security.md`）。

### 記録の識別

根拠欄の記録は、ID・日付・ラベル・環境・対象の版の組で指す。これは識別（記録をどう指すか）の規則である。判定票の行との照合は [README.md](README.md) の R4 が定める。組が重なる（同じ組の記録が base と head、または head の中に複数ある）ときは、根拠を追加した spec の commit と、その commit の中の位置（行・順序）で補って照合する。それでも一意に決まらないときだけ、判定不能とし（判定を要する）、人が区別する。履歴として残した記録（範囲を狭めた差分で、base に同じ形で存在し変えていない記録）と、移管先へ写した記録は、この差分でも後のどの差分でも、確定の範囲を決めず、裏付けにも数えず、R4 の「今回足した記録」にも数えない。履歴の記録は、判定票の「履歴として残した記録」の欄の記録で識別する（記入できるのは、選ばれた種類によらず、その行で範囲の分類が「狭める」ときだけで、base で範囲の内にあった記録に限る。分類が「狭める」でない行ではその欄は `-` だけ）。写した記録は、写した記録を受け取る全ての行（移管・移管（検討中）・置き換え先）の「写した記録」の欄と「消える記録の出所」で識別し、見分けられなければ止める（R1）。履歴の記録・写した記録も、合格でない記録の検査（(ii)・(iii)）からは外さない。判定票の参照は、1 件の記録に解決でき、その記録が今回の差分で足されたものである場合に限り通す（base にある旧い記録を指す参照は、同じ組でも通さない。R4）。1 件に解決できない参照は、人が区別して 1 件に決めるまで通さない。判定票（[judgment-form.md](judgment-form.md)）と [README.md](README.md) の U-9 は、この節を引く。

### 例（架空）

```
<br>**確定の記録**: 日付=2026-01-01 ; ラベル=〔実機〕 ; 環境=架空の環境 A ; 対象の版=abc1234 ; 出典=XMPL-1 の試験 T-1 ; 出力=終了コード 0・ok=3 ; 件数=3/3 ; 結果=合格 ; 記入者=利用者 ; 判定者=利用者
```

`XMPL-1` の根拠欄にこの行を足し、環境 A の範囲に限って確定にする、という使い方である。

## 検証の種類のラベル

ラベルの意味は `docs/spec/02-poc-plan.md` の「検証の種類のラベル」節と、`04-behavior/README.md` の ID 規約 (a) に従う。結果の記録でも同じラベルを使い、種類の違う結果を混ぜて合否を数えない。

| ラベル | 要約 |
|---|---|
| 〔実機〕 | 実際の PostgreSQL・ブラウザ・プロセスで確かめた |
| 〔仮想〕 | 仮想 authenticator で確かめた |
| 〔人の操作〕 | 実機の authenticator を人が操作して確かめた |
| 〔モック〕 | 相手が stub・模擬である |
| 〔資料〕 | 一次資料を読んで確かめた。実行しない |

- 〔仮想〕の結果で確定にする項目は、根拠欄に「仮想 authenticator の範囲」と明記する（ID 規約 (a)）。
- 〔人の操作〕の記録の証拠の形: 人が操作した事実を `手順=`・`機材の種類=`・`ブラウザの版=`・`実施者=`（`ACPT-8` の記録項目。`02-poc-plan.md` の「記録の形」節も参照）で書き、結果と件数は人が書く。自動では作らない。書かない値: credential ID・user handle・attestation・アカウントが写る画面写し・個体の名前・識別子。4 欄は (2) 以降で必須で、欠けは U-9 の必須欄の条件の検査の対象に入る。
- 〔人の操作〕の記録は (ブラウザ, authenticator) の組ごとに 1 件とし、確定の範囲は記録のある組だけにする。
- ラベルの禁止（〔仮想〕〔モック〕〔資料〕の合格を〔実機〕〔人の操作〕の確定に使わない等）の正本は [README.md](README.md) の「原則」である。ここでは写さない。
- 02 の節には〔未実行〕もあるが、実行していない項目であり、確定の根拠には使わない。
- 各ファイル固有のラベル（〔未確かめ〕〔設計〕等）の扱いは ID 規約 (a) に従う。
