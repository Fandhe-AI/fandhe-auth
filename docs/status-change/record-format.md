# 根拠欄の記録の形式

`ACPT-7` の操作 (1)（試験の記録を根拠欄に追記する）の書式である。書式は暫定で、spec 側での採用は利用者の判定待ち（[README.md](README.md) の U-1）。
例の ID は架空の `XMPL-1` で、実在の ID ではない。

## 形式

根拠欄の末尾に、次の 1 行を `<br>` で続けて追記する。

```
<br>**確定の記録**: 日付=YYYY-MM-DD ; ラベル=〔…〕 ; 環境=… ; 対象の版=… ; 出力=… ; 件数=n/m ; 結果=合格 ; 判定者=…
```

ステータスを変えない追記（試験をしたが確定にしない）は、見出しを `**試験の記録**` にして同じ形で書く。`**確定の記録**` は、`ACPT-7` の操作 (1) の「試験の記録」のうち、ステータスを変える場合に当たる。

- `**確定の記録**` の見出しと判定者の値は、判定した本人（人）が書く。
- 自動の収集・AI の下書きは `**試験の記録**` だけを書く。判定者の欄は空（未判定）にし、人が判定したら埋める。確定の記録では判定者は必須である。
- `**試験の記録**` の結果欄: 自動・AI は結果欄を書かず、別の欄 `出力=`（終了コード・件数などの機械の出力）だけを書く。結果欄（5 値）は人が書く。人が書く前の結果欄と件数欄は空（未記入）にしてよい。〔資料〕〔人の操作〕の試験の記録は自動では作らない。結果を確定の根拠にするかの判断も人が書く。
- 結果欄は記録の値で、確定にするかの判定とは別である。判定は [judgment-form.md](judgment-form.md) の「判定」欄に人が書く（同様式の「結果（記録の値）」と「判定」の区別を引く）。
- 判定者は個人名ではなく役で書く（利用者、または指名の記録への参照）。

記録は 3 つの時点に分ける。必須の欄は時点で変わる。

| 時点 | 書く人 | 必須の欄 |
|---|---|---|
| (1) 判定前の `**試験の記録**`（自動の収集） | 自動でよい | 日付・ラベル・環境・対象の版・出力。件数・結果・判定者は空欄でよい（`件数= ; 結果= ; 判定者=`）。機械が出した件数・終了コードは `出力=` に残す |
| (2) 人が結果を記入した `**試験の記録**` | 人 | (1) に加えて、件数・結果（5 値のどれか）。判定者は空（未判定）のままでよい。結果が `未実施`・`実行できない` のときの日付・件数は下の欄の表に従う |
| (3) `**確定の記録**` | 人 | 日付・ラベル・環境・対象の版・出力・件数・結果・判定者の全て |

| 欄 | 必須の時点 | 内容 |
|---|---|---|
| 日付 | 全て | 試験をした日（`YYYY-MM-DD`）。結果が `未実施`・`実行できない` のときは、記録した日（実行を試みた日があればその日） |
| ラベル | 全て | 検証の種類。下の 5 種から選ぶ |
| 環境 | 全て | 確かめた環境。確定にする範囲はこの環境に限る（[scope-rule.md](scope-rule.md)）。結果が `未実施`・`実行できない` のときは、試す予定だった環境または試行した環境を `環境=予定:…` と書き、特定できなければ `環境=-` と書く。どちらも確定の範囲の根拠にならない |
| 対象の版 | 全て | 試験した対象の版（commit の短い sha 等） |
| 件数 | (2)・(3) | `n/m`（合格 n・対象 m。m の定義は「結果の値」の節）。人が合格件数を確かめた段階で埋める。(1) では空でよい。結果が `未実施`・`実行できない` のときは、対象数 m が分かる場合は `件数=-/m`、分からない場合は `件数=-/-` と書く（合格件数は実行していないので `-`） |
| 出力 | 全て | 試験の道具の機械の出力（終了コード・件数など）。機械の出力が得られた場合は必須（自動の収集・人の記入のどちらでも）。得られなかった場合は `出力=なし` と書く。判定前の件数はここに残す |
| 結果 | (2)・(3) | `合格`・`不合格`・`判定不能`・`実行できない`・`未実施` のどれか 1 つ。人が書く。(1) では空でよい |
| 判定者 | (3) | 判定した人の役（利用者、または指名の記録への参照）。AI・自動処理を書かない。(1)(2) では空（未判定）で、人が判定したら埋める |
| 判定の記録 | 任意 | 人の判定の記録への参照（[judgment-form.md](judgment-form.md)） |

件数欄も結果欄と同じく、自動・AI は書かない（機械の件数は `出力=` に残す）。
`**確定の記録**` の結果は `合格` に限る。合格以外なら確定の記録にせず、`**試験の記録**` として残す（逆戻りの提案は [scope-rule.md](scope-rule.md)）。
結果欄に値を書くのは人だけで、書いた時点で (2) になる。値を書いた後は 5 値のどれかでなければならない（空欄に戻さない）。

### 結果の値

- 値は `02-poc-plan.md` の「記録の形」節の 4 値（合格・不合格・判定不能・実行できない）に合わせる。`ACPT-8` の「未実施として記録」に当たる値として `未実施` を足す。
- 合格以外は合格に数えない（`ACPT-8`）。
- 結果は対象の ID の期待・成功基準で決め、件数の多寡では決めない。`件数=n/m` で n<m なら合格にしない。m は対象の ID の期待・成功基準が数える対象の数で、成功基準が「少なくとも一方」のように数える場合は、その単位で n/m を書く。

### 書き方の制約

- 欄の区切りは ` ; `（空白・セミコロン・空白）。
- 値に `|`・`;`・`<br>` を含めない（表の列・欄・追記の区切りと衝突するため）。
- 秘密値・実機の名前・ホームのパス・内部のアドレスを書かない（`.claude/rules/security.md`）。

### 例（架空）

```
<br>**確定の記録**: 日付=2026-01-01 ; ラベル=〔実機〕 ; 環境=架空の環境 A ; 対象の版=abc1234 ; 出力=終了コード 0・3 件 pass ; 件数=3/3 ; 結果=合格 ; 判定者=利用者
```

`XMPL-1` の根拠欄にこの行を足し、環境 A の範囲に限って確定にする、という使い方である。

## 検証の種類のラベル

ラベルの意味は `docs/spec/02-poc-plan.md` の「検証の種類のラベル」節と、`04-behavior/README.md` の ID 規約 (a) に従う。結果の記録でも同じラベルを使い、種類の違う結果を混ぜて合否を数えない。

| ラベル | 要約 |
|---|---|
| 〔実機〕 | 実際の PostgreSQL・ブラウザ・プロセスで確かめた |
| 〔仮想〕 | 仮想 authenticator で確かめた |
| 〔人の操作〕 | 実機の authenticator を人が操作して確かめた |
| 〔モック〕 | 相手が stub・模擬である |
| 〔資料〕 | 一次資料を読んで確かめた。実行しない |

- 〔仮想〕の結果で確定にする項目は、根拠欄に「仮想 authenticator の範囲」と明記する（ID 規約 (a)）。
- 〔仮想〕の合格で〔実機〕〔人の操作〕の項目を確定にしない（`ACPT-7` の期待の 1 文目。仮想 authenticator と実機の関係は `ACPT-8` で、〔実機〕の側だけに掛かる。〔人の操作〕の根拠は `docs/spec/02-poc-plan.md` の「Go/No-Go 判断基準」節と `.claude/rules/verification.md`）。〔モック〕〔資料〕の合格を〔実機〕〔人の操作〕の確定に使わない（禁止）。根拠は `02-poc-plan.md` の「Go/No-Go 判断基準」節（〔モック〕〔仮想〕〔資料〕の合格を〔実機〕〔人の操作〕の合格に読み替えない）と、`.claude/rules/verification.md`（〔仮想〕〔モック〕の合格で〔実機〕〔人の操作〕を確定扱いしない）。`ACPT-7` の期待の 1 文目が名指すのは〔仮想〕だけだが、禁止の範囲はそれに限らない。
- 02 の節には〔未実行〕もあるが、実行していない項目であり、確定の根拠には使わない。
- 各ファイル固有のラベル（〔未確かめ〕〔設計〕等）の扱いは ID 規約 (a) に従う。
