# 検討中から確定への変更の手順

`TASK-74`（検討中から確定への変更の手順と集計の道具）の手順書。根拠は `ACPT-7`（`docs/spec/04-behavior/acceptance-retest.md`。操作 (1)〜(4)・期待）である。
本文は写さず、ID で引く。ステータスの正（SSOT）は spec repo の `04-behavior/` で、この repo の `docs/spec` は直接編集しない（`.claude/rules/spec-reference.md`）。

この文書は手順の説明であり、確定への変更そのものではない。判定は人が行う。

## 原則

- 道具は「人の判定が要る変更」を漏れなく検出して止めるだけで、変更が正しいかは判定しない。正しさは人が判定票で判定する。検出の範囲は広く取り、判別できなければ止める（fail-closed）。
- 語の使い分け: 「判定を要する」は人の判定（段 3）を経れば通せることを指す。「通さない」は通す経路が無く、直して出し直すことを指す。道具が「止める」のは、どちらの場合も検出して終了コードで止める動作である。
- AI・自動処理は「確定」にしない。確定への変更の判定は人が記録する（`ACPT-7` の期待の 3 文目）。試験の実行と記録の収集は自動でよい。
- 段 3 の対象の commit を AI・自動処理が作らない。trailer を外して検査を通すのは迂回に当たる。PR なしの push は通さないものとし、merge の実行者も人とする。
- ラベルの禁止（この節が正本。他の文書は参照する）:
  - 〔仮想〕の合格で〔実機〕〔人の操作〕の項目を確定にしない（`ACPT-7` の期待の 1 文目）。
  - 〔モック〕〔資料〕の合格を〔実機〕〔人の操作〕の確定に使わない（禁止）。根拠は `docs/spec/02-poc-plan.md` の「Go/No-Go 判断基準」節（〔モック〕〔仮想〕〔資料〕の合格を〔実機〕〔人の操作〕の合格に読み替えない）と `.claude/rules/verification.md`（〔仮想〕〔モック〕の合格で〔実機〕〔人の操作〕を確定扱いしない）。`ACPT-7` の期待の 1 文目が名指すのは〔仮想〕だけだが、禁止の範囲はそれに限らない。
  - 次の 2 点は書き手の読み（厳しい側）である。`ACPT-8` の期待の欄にある仮想 authenticator の合格の扱いは、〔実機〕と〔人の操作〕の両方に掛かると読む（`docs/spec/02-poc-plan.md` の「記録の形」節も参照）。自動の〔実機〕の実行は、authenticator を使う項目では仮想 authenticator に当たると読む（02 の「検証の種類のラベル」節）。この読みにより、authenticator を使う項目は〔人の操作〕だけを認め、DB・プロセスの〔実機〕の項目は〔実機〕を認める。
- 期待が成り立たないときは期待を緩めず、逆戻りの提案として報告する（`ACPT-7` の操作 (4)）。
- 仕様の変更は `04-behavior/` から始め（段 3。ステータスサマリーは `04-behavior/README.md` の中にあり、同じ差分に入れる）、`05-tasks.md` と `spec.md`（自動生成。再生成する）は後で追随させる（段 4。SSOT）。
- 道具が 0 件を返しても、それは判定ではなく材料である（`.claude/rules/verification.md`。ゲートの通過は spec の「確定」ではない）。
- 秘密値・実機の名前・ホームのパス・内部のアドレスを書かない（`.claude/rules/security.md`）。

## 段 3 の対象

段 3 の対象は、spec repo の 1 つの PR の差分のうち、次を含むものである。spec のどのファイルへの変更でも対象になり得る（ファイル単位の除外は無い）。対象かどうかは変更の中身で決める。

- 確定の行（変更の前か後）の全ての文字（ID・優先度・ステータス・前提・操作・期待・根拠欄の全ての文）の変更、行の追加・削除・移管・置き換え。確定の行の根拠欄に `**試験の記録**` を足すことも含む（種類は「試験の記録の追記」で、範囲を変えないことを人が確かめる）。次は例示である: 範囲（環境・条件・版・件数）・ラベル・範囲の語・優先度・前提・操作・期待・引く先・根拠欄の記録以外の文
- 「確定の範囲」の記載（ファイル冒頭・行頭の「確定の範囲」）の変更・削除
- 引く先の変更: 確定の行が引く ID（期待を委ねた ID など）・`01-brainstorm.md` の既存の `A-`・`D-`（引いているかによらない）・`03-poc/**` の全ファイルの変更。引く先の一覧と突き合わせられるまでは要確認（判定を要する。fail-closed）とし、人が段 3(c) で確かめる。参照先だけの変更で確定の行の文字列が変わらないときも、影響を受ける参照元の (ID, 範囲) ごとに今回の版の `**確定の記録**` で再判定する（種類は「引く先の変更」。記録を要し、肯定の値は「確定にする」と同じ）か、確定から検討中に戻す。判定票には、差分の各引く先の変更ごとに、それを示す行を 1 つ以上置く（R2）。確定の行が引いている ID（接頭辞によらない。`D-`・`A-`・`Q-`・`N-n`・`PoC-`・`QP-`・`TASK-` など）を読み替える・置き換える・答える新規の記述（新しい `D-`・`A-`・`Q-`、番号の無い追記を含む）は、引く先の変更として段 3 の対象にする。同じ差分で確定の行から引かれる新しい ID は、参照元の行とあわせて対象に入れ、R2 の照合に含める（変更の前後の参照を比べて確かめる）。どちらにも当たらない新規の追加は、確定の行がまだ引いていないので対象外である
- 移管表の変更・欠番の ID の復活（ステータスによらない）。欠番の ID の復活と、移管表から ID を消す変更は通さない。欠番の見分け方は、道具が番号で機械的に行う（利用者の判定 2026-11-21）: 新しく足す ID の番号が base の時点のそのファイルの同じ接頭辞の最大の番号以下なら欠番の復活、base の移管表に載る ID を行として足すのも復活で、通さない。base の最大 +1 から連続して足す番号（+1, +2, …）は新しい ID で、欠番の復活ではない。連続していない番号（番号を飛ばした）は、ID 規約（新規はファイル内の最大 +1、欠番は再利用しない）から外れるので、種類「番号の飛ばし」（判定を要する。肯定の値は「確認済み」。新しい行自体の種類の行に加えて別に 1 行置く）とする。最初に「通さない」種類（欠番の ID の復活・移管表から ID を消す変更）に当たるかを判定し、当たれば他の種類を見ずに通す道は無い（R6）。移管表に ID を足す変更は、同じ差分で移管元の行が消えるなら「移管」「移管（検討中）」（移管先が検討中のとき。記録は不要で R4 の対象外。判定を要する）「spec の外への移管」「置き換え」の行に含め、行が消えない・base に行が無いなど判別できないときは止める（R1）。載っている ID を消さず、行のステータス・範囲・本文を変えずに移管表の記載だけを直す変更は、種類「移管表の修正」（判定を要する。記録は不要）とする。直した ID を引く確定の行が逆引きで 1 行でもあれば、その行に「引く先の変更」を当てる
- 合格でない記録・空欄の記録を持つ行の削除（検討中の行も。行のステータスによらない）。種類は「削除」で、判定票に旧 ID・base の commit・消える記録の出所を残す
- サマリー（spec repo の `04-behavior/README.md`）の確定の件数の変更、または段 5 の集計と一致しないとき
- 確定の定義と読み方を決める文書（`04-behavior/README.md` の ID 規約・`CG2-4` の段落、各ファイルの適用範囲と冒頭の注記、`02-poc-plan.md` のラベル・記録の形・Go/No-Go 判断基準の節、`ACPT-7`〜`ACPT-11` の行〔対応 ID の欄を含む〕）の変更
- どの行でも `**確定の記録**` の追加・変更・削除。ステータスを変えずに検討中の行へ足す差分は通さない。行が head に残るなら、既存の `**確定の記録**` の変更・削除は、足した記録と見なさず通さない（新しい記録を足し直す）。行（ID）ごと head から消える場合（削除・移管・置き換え元・spec の外への移管）の記録の消滅は、行の変更の一部として判定する（消える記録の出所を判定票に残す。[judgment-form.md](judgment-form.md) の「記録が消えてよい場合」）
- 既存の `**試験の記録**` の削除・書き換え（記入済みの値の変更を含む）。行が head に残るなら、行のステータスによらず対象にし、通さない（検討中の行でも同じ。新しい記録を足して残す）。行ごと消える場合（削除・移管・置き換え元・spec の外への移管）は、上の項と同じく行の変更の一部として判定する。移管・置き換えでは、移管元・置き換え元の結果が合格でない・空欄の `**試験の記録**` を写さずに捨てることは通さない（写すことが必須）。写すときは 1 字も変えない
- 既存の記録の変更。確定の行にある `**試験の記録**` の空欄への記入は、件数・結果・記入者と〔人の操作〕の 4 欄（手順・機材の種類・ブラウザの版・実施者）に限り、判定を要する（種類「試験の記録への記入」）。それ以外の欄への記入、`**確定の記録**` への記入、見出しの変更（`**試験の記録**` を `**確定の記録**` に書き換える場合を含む）、記入済みの値の変更は通さない（今回の差分で足した記録と見なさない）。検討中の行の空欄への記入・追記は、下記のとおり対象外のままとする（削除・書き換えは上の項のとおり検討中の行でも通さない）。確定の行か検討中の行かは、base の状態で見る。同じ差分でステータスを変える行は確定の行として扱う

通すには、同じ差分で足した `**確定の記録**` と人の判定（段 3）を要する。ただし記録を要しない種類（[judgment-form.md](judgment-form.md) の表で「不要」の行）は、人の判定だけで通す（R4 の対象になる条件は R4 の冒頭に書く）。段 3 の対象の全ては、判定票の種類の表の、(ID, 範囲) の単位ごとにちょうど 1 つの種類に当たる（複数当たるときの優先順位も同じ表の下に書いてある）。ただし、記録を要しない種類だけが同じ行に重なるときは、種類ごとに判定票の行を分ける。
種類ごとの扱い（記録が要るか・判定の値）は [judgment-form.md](judgment-form.md) の表が正本で、ここでは写さない。
検討中の行への `**試験の記録**` の追記・結果の記入だけの差分は、対象外である（上の確定の行への追記は、確定の行に限る。結果・件数・記入者・判定者の欄に記入する差分は人の commit に限る）。ただし行が head に残るのに既存の `**試験の記録**` を削除・書き換えるのは、行のステータスによらず対象で、通さない。
確定の行の期待の変更は、段 3 を経ない限り通さない（R6）。
検討中の行の期待を緩める変更は、後で確定にするときの判定材料として人に示す。
道具の未提供の間も同じで、手で確かめる。

## 段 3(c) の確かめる項目

人が確定の前に確かめ、判定の記録に残す。

- 判定者が実際に人であること（道具は判定できない）
- 検証の種類（ラベル）と範囲が、項目の要求に合うこと（U-4 の暫定の集合の外の項目を含む）
- `ACPT-7` の前提の解消（再試験・決定・受け入れ試験が済み、検討中の理由が解けたこと。判定表に D-・TASK- の参照を残す）
- 範囲を分けた場合、分けた残りの検討中の行が同じ差分にあり、互いに ID で引いていること（[scope-rule.md](scope-rule.md)）
- 対象の版が今回の版と一致すること、`spec.md` を比べる基準（比べ方は `tools.md`〔後続の PR〕で定めるまで人が確かめる）
- 確定の行に `**試験の記録**` を足す差分（試験の記録の追記）では、範囲を変えないこと。確定の行の `**試験の記録**` への記入（空欄への記入）では、許された欄だけで、記入済みの値・見出し・他の欄を変えていないこと
- 実施者が手順を行う担当（利用者）であること（`D-2026-10-27-5`）
- 引く先の逆引き: 変更した ID・`D-`・`A-`・ファイルの path・`03-poc` のファイルに対応する `PoC-n`・`QP-n`・節の名前、上の新規の記述が読み替える・置き換える・答える ID を鍵にして、全ての確定の行を探す。範囲の表記（`〜`）は展開して照合する。規則の文書の変更では、逆引きではなく、その規則を使う全ての確定の行を影響を受ける行とする（例: ラベルの定義の変更なら、そのラベルを持つ全ての確定の行）。引く先は推移的にたどる（Y が X を引き、X が Z を引くなら、Z の変更も Y に及ぶ）。探した結果（見つかった行、または 0 行とその理由）を判定票に残す。この逆引き（ID・接頭辞・節の名前・`〜` の範囲の展開・推移的な参照）が引く確定の行を 1 行でも見つけたら、「0 行とする理由」では通さず、見つかった行ごとに判定票の行を分ける。理由を書けるのは、引く先の変更では逆引きで 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）のときだけで、そのときも人の判定を要する。道具は突き合わせられないものを要確認（判定を要する）にし、中身の判定は人が行う
- 行ごと消える記録（削除・移管・置き換え元・spec の外への移管）は、判定票の「消える記録の出所」（base の commit と元の ID）が書かれ、同じ ID の行が head に残っていないこと。移管先へ写した記録が 1 字も変わっていないこと。範囲を狭めた行の旧い記録が、base に同じ形で存在し変えておらず、判定票の「履歴として残した記録」の欄に書かれていること、履歴の記録を持つ行の行頭の範囲が消えていないこと、狭めた後の範囲の環境ごとに今回の記録があること
- 範囲の分類（[judgment-form.md](judgment-form.md) の「範囲の分類」）が差分と一致すること。同じ ID・同じ版で範囲の書き方が違う合格でない記録を「重ならない」と判定したときは、その根拠が判定票にあること
- 欠番の判別の限界（最大の番号の行を以前に消した後の再使用）を踏まえ、新しい ID の番号を原文で確かめること（道具の限界の節）。連続していない番号は「番号の飛ばし」の行があること
- 写した記録を受け取る行（移管・移管（検討中）・置き換え先）で、「写した記録」の欄が移管元・置き換え元の記録（合格でない・空欄を含む）と 1 字も違わず一致していること
- 確定にする・範囲を広げる行で、同じファイルで削除済みの旧 ID の判定票（種類「削除」）を探し、期待の比較の結果が「削除済みの旧 ID との比較」の欄にあること（0 件なら「0 件」）
- 同じ差分で消える行（確定の行・検討中の行）の記録（base の commit で引く）に、合格でない記録か空欄の記録があるとき、消す差分と確定にする差分を分けていないか。分けていれば、消えた行の記録を参照して、同じ中身を別の ID で足し直していないことを確かめ、判定票に残す

## 道具

`scripts/spec-status-count.sh`（集計と README の表との突き合わせ）と `scripts/spec-status-check.sh`（全行の検査と変更の検査）は、後続の PR で追加する。
使い方・終了コード・検出の区分は `tools.md` に書く（同じく後続の PR）。この PR の時点では、どちらも存在しない。

### 道具の限界

- 欠番の判別（番号による機械的な見分け）の限界: base の最大の番号の行を以前の差分で消していると、base の最大が下がっており、その番号の再使用を検出できない。段 3(c) で人が確かめる。同じ差分で +1, +2, … と連続して足す番号は新しい ID として扱い、連続していない飛ばしだけを「番号の飛ばし」（判定を要する）にする。
- 同じ差分で消える行（確定の行・検討中の行）の合格でない記録・空欄の記録は、差分を分ければ道具が結び付けられない（行が同じ中身かは判定できない）。分けた差分の確認は段 3(c) で人が手で行い、道具では止められない。
- 道具は spec を読むだけで、書き込まない。検出の件数が 0 でも、確定への変更が人の判定であったことの証明にはならない。
- 誰が記入したかは証明できない。spec repo の commit の作者・trailer では人と AI を区別できず（AI が手伝った commit が多数ある）、判定者・記入者の欄は人の自己申告である。
- 件数 0 は代理の指標である。最終の確かめは人が行う（`ACPT-7` の期待の 3 文目。`.claude/rules/verification.md`）。
- 規則と道具の変更は人のレビューを経る。陽性の fixture を減らさない。
- spec repo の CI では流さないので（U-10）、道具が止めるのは材料であり、強制ではない。
- 道具は、突き合わせられない引く先の変更を要確認（判定を要する）として止める（0 件は通過を意味しない）。判定票の「0 行とする理由」は、引く先の変更では逆引きで 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）のときだけ書け、人の自己申告で、道具では確かめられない（逆引きで確定の行が 1 行でも見つかれば、理由では通さない）。中身の判定は人が段 3(c) で行う。
- spec repo は private で、実データの検査はローカルに限る。権限のない環境（CI・外部の貢献者）では、検査不能として扱う（`.claude/rules/spec-reference.md`）。

## U-9 の要件（暫定。利用者の判定待ち）

PR 1 の手順は、道具が無くても人だけで回ることを正とする。道具への要件は次の R1〜R7 だけを残す。
それぞれの細目（版の比べ方・単位の書き方・参照の手段）は `tools.md`（後続の PR）で fixture とともに定める。決まるまでは段 3(c) で人が確かめる。

- **R1**: 道具は検出して止めるだけで、変更の正しさは判定しない。判別できなければ止める（fail-closed）。要確認・検査不能・解釈できない行は、0 でない終了コードで止め、人が解くまで進めない。
- **R2**: 差分と判定票は両方向で一致する。差分の段 3 の対象の全て（単位は、行ごとの変更ごと）に判定票の行があり、判定票の全ての行が差分にある。引く先・規則の文書の変更は、差分の変更（変更した ID・`D-`・`A-`・path・`03-poc` のファイル・規則の文書の節）ごとに、それを「対応する引く先・規則の文書の変更」の欄に挙げる判定票の行（影響を受けた行の再判定・逆戻りの行、または 0 行の理由の行）が 1 つ以上あり、判定票のその欄の値の全てが差分にある（両方向）。複数の引く先を同じ PR で変えても、行ごとに対応が分かる。
- **R3**: 判定の値は、変更の種類ごとの肯定の値だけを通す。種類と肯定の値の対応は [judgment-form.md](judgment-form.md) の表が正本で、ここでは写さない。否定・保留・空・「指摘あり」は通さない。
- **R4**: 記録の照合。差分の後で確定で、かつ差分で段 3 の対象に触れた行・範囲は、全て照合の対象とする。ただし、記録を要しない種類（[judgment-form.md](judgment-form.md) の表で「不要」の種類。確定から検討中に戻す・削除・移管（検討中）・番号の飛ばし・spec の外への移管は、head が確定でない、または照合する行が無いので、そもそも対象に入らない）のうち、試験の記録の追記・試験の記録への記入・移管表の修正は、その行に記録を要する種類の変更が 1 つも無いときだけ対象外とする。1 つでもあれば、その種類が当たり、R4 を適用する。規則の文書・引く先の変更で影響を受ける確定の行も対象に入れる（引く先の変更では逆引きで 0 行、規則の文書の変更ではその規則を使う確定の行が 0 行（ラベル・範囲の語の定義の変更なら、該当のラベル・語を持つ確定の行を数えて 0 行）のときだけ、その理由を判定票の行として必須にし、人の判定を要する。1 行でも見つかれば理由では通さない）。ファイル冒頭の「確定の範囲」の記載を広げたときだけ、そのファイルの全ての確定の行の (ID, 新しい範囲) を対象にする。行頭の範囲を広げたときは、その行（と範囲）だけを対象にする。「0 行とする理由」の判定票の行は、照合する確定の行もラベルも無いので、R4 とラベル照合の対象外で、理由と人の判定が必須である。対象の (ID, 範囲) ごとに、次を全て満たす。
  - 今回の差分で足した `**確定の記録**` がある（base にあった記録で代替しない。既存の記録の変更は、段 3 の対象の「既存の記録の変更」に従い、足した記録と見なさない）。記録は判定票の行の (ID, 範囲, ラベル, 対象の版, 結果) と一致する（照合。記録の指し方〔識別〕は [record-format.md](record-format.md) の「記録の識別」節）。判定票の「根拠欄の記録の参照」は、その節の組（ID・日付・ラベル・環境・対象の版）で 1 件の記録に解決でき、組が重なるときは commit と記録の位置で補う（[judgment-form.md](judgment-form.md)）。解決した記録自体が今回の差分で足されたものである。base にある旧い記録を指す参照・複数の記録に解決される参照・解決できない参照は通さない
  - 範囲（環境・条件・版・件数）: 変えない行は base の上限（ファイル冒頭・行頭の確定の範囲）で評価する。広げた範囲は、head の上限の中にあり、かつ今回の記録で裏付けられることを要する。触れたが広げない行は、base と head の上限の小さい方で評価する。今回の差分で足した・変えた記録の環境が上限の外なら通さない。それ以外の旧い記録の環境が行頭の範囲の外・食い違いのときは、判定を要する（止めて人が解く）。例外は、範囲を狭めた差分で base に同じ形で存在し今回変えていない記録（履歴として残した記録）だけで、判定票の「履歴として残した記録」の欄に書かせる（履歴の欄に記入できるのは、選ばれた種類によらず、その行で範囲の分類が「狭める」ときだけで、base で範囲の内にあった記録に限る（分類が「狭める」でない行は `-` だけ）。写した記録は、写した記録を受け取る全ての行（移管・移管（検討中）・置き換え先）の「写した記録」の欄に必ず列挙させ、後の差分ではその欄と「消える記録の出所」で見分ける（見分けられなければ止める。R1））。人が解いた旧い記録の判定は、判定票の「範囲の外の旧い記録の判定」の欄に書かせる（肯定の値は「確認済み」。この判定は範囲を広げず、その記録は裏付けにも範囲にも数えず、(ii)・(iii) からも外さず、「範囲が重ならないとした根拠」の代わりにもならない）。範囲の記載の環境ごとに、今回の記録の裏付けがある。履歴として残した記録と、移管先へ写した記録は、この差分でも後のどの差分でも、確定の範囲を決めず、裏付けにも数えず、R4 の「今回足した記録」にも数えない（[judgment-form.md](judgment-form.md) の「記録が消えてよい場合」・`scope-rule.md`・[record-format.md](record-format.md) の「記録の識別」）。履歴の記録または写した記録を持つ行（base でも head でも）で行頭の範囲を消す・持たない形にする変更は通さない。履歴の記録・写した記録も、合格でない記録の検査（(ii)・(iii)）からは外さない
  - 対象の版が今回の版と一致する（旧版の記録で代替しない。`scope-rule.md`）
  - 合格の記録があっても、次の全てを検査し、合格以外（結果が `合格` でない・n<m・m=0・`-` を含む等）が 1 件でもあれば通さない（合格の記録で打ち消さない）。(i) 差分で新しく足した・変えた全ての `**確定の記録**`。(ii) head にある同じ (ID, 範囲, 版) の全ての `**試験の記録**`（今回足したもの・今回空欄に記入したもの・変えていないものの全て。head で結果欄が空欄のものも、合格でないものとして数える。結果が `合格` でも件数欄が空欄・`n/m` の形でない記録は、合格でないものとして数える。未完の試験が残っていれば確定にしない）。(iii) base にある同じ (ID, 範囲, 版) の合格でない記録（`**試験の記録**` を含む）。ただし base で結果欄が空欄だった記録は base では数えず、今回記入した値を (ii) で head で見る。移管・置き換えでは、移管表で対応づけた移管元の ID の base の記録も同じ (範囲, 版) として (iii) に含める。同じ ID・同じ版で、範囲の書き方が違う合格でない記録（範囲の記載が違う・範囲が無い・環境の表記が違うなど）は、範囲の書き方によらず判定を要する。重なるかは人が判定し、重なるなら通さず、判別できなければ止める（R1）。「重ならない」と判定したときは、その根拠（範囲の対応）を判定票の「範囲が重ならないとした根拠」の欄に必須で残す
  - 行をまたぐ照合: 同じ差分で消える行（削除・spec の外への移管・移管元・置き換え元を含む。確定の行でも検討中の行でも同じ。検討中の行の削除で `**試験の記録**` が消える場合も掛かる）の base に、合格でない記録か結果欄が空欄の記録が 1 件でもあり、かつ同じ差分で別の行（移管先・置き換え先を除く。それらは同じ版の照合の (iii) の移管元の句に任せる）を確定にする・確定の記録を足す・範囲を広げる変更があれば通さない（同じ中身を別 ID で足し直す経路を塞ぐ。同じ中身かは道具が判定できないので、一律に止める）。消す差分と確定にする差分を分けた場合は、消す差分の判定票に種類「削除」の行（旧 ID・base の commit・消える記録の出所）を求め、後続の確定にする差分の段 3(c) で、同じファイルで削除済みの旧 ID の判定票を探し、期待の比較の結果を判定票の「削除済みの旧 ID との比較」の欄に残させる（道具の限界の節）
  - 結果が `合格`。結果が合格以外の `**確定の記録**` の追加は、行が検討中でも無条件で通さない（合格以外を `**試験の記録**` として残すだけなら対象外で段 6。ただし同じ (ID, 範囲, 版) の確定の記録を足すなら、上の打ち消さない検査で通さない）
  - 件数が `n/m` の形で n=m の数値で、対象の数が正（m≥1。`0/0` を通さない）である。形でない・n<m・n>m（形式の不整合）・m=0・`-` を含むときは通さない
  - 必須欄がある（〔人の操作〕の確定の記録では `手順=`・`機材の種類=`・`ブラウザの版=`・`実施者=` を含む。〔人の操作〕は (ブラウザ, authenticator) の組ごとに 1 件で、確定の範囲は記録のある組だけ）
  - ラベルが (ID, 範囲) の要するラベルと一致する（下の注）。評価の順序: 要するラベルが未定なら、記録のラベルが〔人の操作〕でも、ラベルの照合より先に通さない（U-4）
  - ラベルが〔仮想〕なら、環境に範囲の語（「仮想 authenticator の範囲」。ID 規約 (a)）がある
  - 環境が `環境=予定:…`・`環境=-` でない
  - 判定者・記入者の欄が空でなく、AI・自動処理を示す値でない（代理の検査。人かどうかは道具では判定できず、人が段 3(c) で確かめる）
- **R5**: 判定票は PR に結び付く。判定票に spec の base と head の commit の欄があり、検査する差分と一致する。head は判定票を保存する前の対象の PR のブランチの先頭で、判定票を対象の PR のブランチにコミットしない（コミットすると head が変わり一致しなくなる）。判定票は対象の PR のブランチとは別の参照に置き、保存しても検査の対象の head が変わらないようにする。置き場の path と参照の形は U-8 と同じく未定（利用者の判定待ち）。
- **R6**: 機械で分かる変化は道具が種類を決め、判定票と食い違えば止める。種類の語彙・優先順位・範囲の分類・各種類の条件（移管先・置き換え先の行頭の範囲の要件、移管元・置き換え元の合格でない・空欄の `**試験の記録**` を写すことの必須、写した記録の扱いを含む）は [judgment-form.md](judgment-form.md) が正本で、ここでは写さない。決め方の最初の段で、「通さない」種類（欠番の ID の復活・移管表から ID を消す変更・既存の記録の変更・検討中の行への確定の記録の追加）に当たるかを判定し、当たれば他の種類を見ずに通さない。次に、機械で分かる対応: 検討中から確定・確定での行の追加→「確定にする」、確定から検討中→「確定から検討中に戻す」、行が head に無く移管表にも載らない→「削除」、移管表に載る追加→移管先が確定なら「移管」（条件は judgment-form の表。移管元が検討中、または移管先が前提・操作・期待や範囲を変える場合は「確定にする」〔範囲を広げるなら「範囲を広げる」〕とし、R4 を適用する）、移管先が検討中なら「移管（検討中）」、移管先が spec の外の ID→「spec の外への移管」、移管表の記載だけの変更→「移管表の修正」、連続していない新しい番号→「番号の飛ばし」を別に 1 行（引く先の削除は「引く先の変更」も当たる）。記録を要しない種類（「試験の記録の追記」は、記録を要する種類の変更が無く、`**試験の記録**` を足すだけ。「試験の記録への記入」は、許された欄の空欄だけ。「移管表の修正」は、行と載っている ID を変えない）の条件に外れる変更は、記録を要しない種類とは認めず止める。記録を要しない種類は、`judgment-form.md` の表で「不要」の種類だけである。移管・範囲を狭める変更・文面の変更にも記録なしの例外を設けず、R4 の記録と人の判定を要する。確定の行の前提・操作・期待の変更は、誤字の修正を含めて「確定にする」（今回の版の合格の確定の記録が要る）か「確定から検討中に戻す」に限り、「文面の変更」では通さない。ただし、範囲の拡大が重なるときは、優先順位で「範囲を広げる」とし、変更後の期待に対する今回の版の合格の確定の記録を必須にする（「確定にする」と同じ要件を含む）。誤字のような変更の扱いは利用者の判定待ちで、決まるまでこの扱いに限る。「文面の変更」は、前提・操作・期待以外の確定の行の文面と「確定の範囲」の記載に限る。範囲の記載の分類（狭める・広げる・変更なし・比べられない）は judgment-form の「範囲の分類」が正本で、新しい `**確定の記録**` を足す差分で比べられないときは「範囲を広げる」に固定し、判別できなければ止める（R1）。
- **R7**: ラベルの割り当てが未定のとき、判定票の種類の表の「ラベル未定のとき」の欄が「通さない」の種類（「確定にする」「範囲を広げる」「範囲を狭める」「移管」「置き換え先が確定の行の置き換え」「文面の変更」「引く先の変更」「規則の文書の変更」と確定での行の追加）は、R4 のラベルの項で通さない（人が割り当てるまで）。ただし、「0 行とする理由」の行は照合する行もラベルも無いので、ラベルが未定でも止めない。「止めない」の種類（確定から検討中に戻す・削除・移管（検討中）・番号の飛ばし・spec の外への移管・試験の記録の追記と記入・移管表の修正）は、ラベルが未定でも止めず、R4 を求めない（他の変更が重なれば、その種類の欄に従う）。

**変更の種類**: 語彙と、種類ごとの記録の要否・判定の値は [judgment-form.md](judgment-form.md) の表が正本である（「確定にする」「範囲を広げる」「範囲を狭める（分割）」「確定から検討中に戻す」「移管」「spec の外への移管」「削除」「置き換え」「試験の記録の追記」「試験の記録への記入」「移管表の修正」「文面の変更」「引く先の変更」「規則の文書の変更」等。段 3 の対象は全て、ちょうど 1 つの種類に当たる）。

**違反の例**（R1〜R7 の例示で、網羅ではない）: (i) 段 3 の対象を含む PR に判定票が無い、または参照されない／(ii) 判定票の行が差分と一致しない／(iii) 判定の値が肯定の値でない／(iv)「確定にする」「範囲を広げる」の対象に対応する `**確定の記録**` が無い／(v) 記録の対象の版が今回の版と一致しない／(vi) 結果が `合格` 以外・件数が n<m・m=0 または `-` を含む／(vii) 必須欄の欠け・環境が `環境=予定:…`・`環境=-`・ラベルの不一致・判定者・記入者が空、または AI・自動処理を示す値。

**注（ラベル）**: authenticator を使う (ID, 範囲) は〔人の操作〕だけを認める（自動の〔実機〕の実行は仮想 authenticator に当たると読み、通らない）。DB・プロセスは〔実機〕を認める。〔仮想〕〔モック〕〔資料〕はどちらも通らない。要するラベルは U-4（暫定）である。ラベルは自己申告で、通っても〔人の操作〕だったことの証明にはならない（段 3(c) で人が確かめる）。

**全行の不変条件（段 5）**: 全ての確定の行にラベル付きの根拠がある（数え方は U-11。結果は材料）。〔仮想〕の確定に範囲の語がある（ID 規約 (a)）。サマリーの確定・検討中・合計が表の行の集計と一致する（不一致は通さない）。
