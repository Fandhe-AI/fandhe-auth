# Hub の検証用 stub と実物との差

`TASK-7`（親 Issue #58）の成果物のうち「実物との差を書いた文書」。本段は Issue #69。
対象は `crates/hub-stub`（`fandhe-auth-hub-stub`）。

この文書は stub の作りと、実物の Hub との差を書く。判定・「確定」への変更・差の受け入れは人が行う（`ACPT-7`）。
「書き手の読み」は spec に定めが無く、書き手が置いた仮定であり、確定ではない。

## 1. 位置づけ

- stub は試験専用で、実物の Hub ではない。stub の合格を実物の Hub の合格に数えない（`A-2026-10-28-9`、`ACPT-7`）。
  AI レビューや stub の試験の合格だけで安全と確定しない（`CG-2`）。
- Hub が所有する値（秒・間隔・上限・閾値など）はこの repo に置かない。Hub の ID で引く（`A-2026-10-28-1`）。
  この文書にも数値を書かない。
- spec の本文は写さない。ID で引く。
- 模擬の項目と Hub の ID の照合の表、差し替え先の MS-10 の TASK は `TASK-7` の次の段（Issue #70）で本文書へ足す。

## 2. 全体に共通する差

| 項目 | stub | 実物との差 |
| --- | --- | --- |
| 実行モデル | sans-IO・同期。HTTP・TLS・ネットワーク・環境変数・ファイルを持たない（`DPOL-32`） | 実物は通信を伴う。通信の失敗・遅延・再接続の挙動は stub に無い |
| 時刻 | 引数 `now`（UNIX 秒）で受け、時計を読まない。秒未満の値は module ごとに切り上げ・切り捨てで扱う | 実物は時計を読む。秒未満の境界は stub で確かめられない |
| 署名 | 試験が実行時に生成する試験用の鍵。ES256 だけ（`SIGN-1`・`SIGN-6`） | 実物が使いうる他の `alg` は模さない。鍵の保管・ローテーションも模さない |
| URL・ホスト | 文字列で受けるだけで、参照も取得もしない（`jwks_uri` を含む） | 実物は名前解決・接続・証明書の検証を行う（`SIGN-16`・`DPOL-46` の向き） |
| 実物の口への配線 | 無い。`AuthPort`・`ChangeFeedPort`・`AuthJwksPort` は試験側の偽の口 | 実物の口（`backend`）との結線は後続のタスクの担当 |
| 設定の値 | すべて `StubValue` の「仮置き」の印付きで、既定値を持たない（#67） | 実物の値は Hub が正本。stub の値を本番の値として扱わない |
| 判定の主体 | 受理・拒否の規則をコードに固定する | 実物の Hub の規則は Hub 側の実装が正。stub が実物と一致する保証は無い |

## 3. 模擬の口ごとの差

各節は「stub がすること」「実物との差・判定しないもの」「書き手の読み」の順に書く。

### 3.1 本人トークンの提示の受け口（`presentation::IdentityTokenReceiver`、#60）

- stub がすること: 試験が生成した鍵で署名された本人トークンの署名と基本のクレームを確かめ、結果を記録する
  （`CLM-1`・`CLM-2`・`CLM-17`・`CLM-21`・`CLM-26`・`CLM-28`）。`exp == now` は拒否（`SIGN-17`）。
- 実物との差・判定しないもの: Hub が所有する値（有効期限の上限・`iat` の許容など）は判定しない。
  期待値の `issuer`・`audience` は試験用の仮の値で受ける。
- 書き手の読み: 「Hub へ提示する」向きの規則として `CLM-21`・`CLM-26`・`CLM-28` を読んでいる。

### 3.2 assertion による口の呼び出し（`assertion::HubAssertionCaller`、#61）

- stub がすること: `private_key_jwt` の assertion を組み立てて署名し、`AuthPort` へ渡して受理・拒否を記録する
  （`OCL-21`・`OCL-23`・`OCL-30`）。
- 実物との差・判定しないもの:
  - assertion の検証部は置かない。検証は本体（core）の担当（`OCL-22`〜`OCL-28`・`SIGN-7`・`SIGN-56`）。
  - ヘッダの `typ` を付けない。`OCL-21`〜`OCL-28` に定めが無いため。Hub `AUTHC-39` との照合は #70。
  - `jti` の一意性を持たない。重複の作り分け（`OCL-27`）のため、呼び出し側が持つ。
  - form の符号化（`application/x-www-form-urlencoded`）はしない。名前と値の並びまで作る。
- 書き手の読み: Issue の文言は「受けて検証する」とも読めるが、`TASK-7` と `OCL-21` に従い Hub が出す側とした。

### 3.3 失効の通知の受け口（`logout::LogoutTokenReceiver`、#62）

- stub がすること: Logout Token を検証して受信を記録し、何を受け、どの `sid` が届き、重複があるかを数えられるようにする
  （`RVPG-2`・`RVPG-7`・`RVPG-14`・`RVPG-28`）。`typ` は `logout+jwt` に固定（`SIGN-9`・`SIGN-10`）。
- 実物との差・判定しないもの:
  - Hub が所有する値（`exp − iat` の上限など）は判定しない。
  - 送信器・outbox は本体側の担当で、stub に無い。実物の Hub の適用処理（セッションの失効の実行）も模さない。
- 書き手の読み:
  - 同じ `jti` の再受信は拒否せず、重複の印を付けて記録する。適用は一度だけ数える（`RVPG-28`）。
  - `sid` を持たない形の grouped claim の名前は仮で、`RVPG-14` の正本に合わせて確かめる。

### 3.4 変更のフィードの取得（`feed::ChangeFeedFetcher`、#63）

- stub がすること: assertion で `ChangeFeedPort` を呼び、返った項目を取り込む動きを駆動する
  （`OCL-21`・`OCL-30`・`RVPG-39`・`RVPG-40`）。取得間隔の下限の前の取得は口へ届かせない。
- 実物との差・判定しないもの:
  - 項目の形は検討中（`RVPG-38`・`RVPG-41`、Hub `AUTHC-35`）。
  - 種別と版による適用の順序（`RVPG-22`・`RVPG-23`）は判定しない。
  - 取得の周期の値は Hub が正本で、spec 上は未決。
- 書き手の読み:
  - 経過がちょうど下限なら取得してよい。時計の巻き戻りは安全側で拒む。秒未満の下限は切り上げる。
  - 口に届いた要求は、拒否されても間隔の計数に入れる。
  - `sid` も grouped claim も持たない項目は、本人単位の項目（`RVPG-41`）として中身を保持するだけにする。
- 追跡: 本体の `ChangeFeed::read_since`（仮称。`RVPG-42`）の形が決まるまで、`feed.rs` の `TODO(TASK-7)` が残る。

### 3.5 生存確認の受け口（`heartbeat::HeartbeatReceiver`、#64）

- stub がすること: 受信を記録し、`status` で生存・非生存の両方を作り出せる（Hub `AUTHC-20`・`AUTHC-21`）。
  DB の状態・件数は記録するだけで、生存の判定に使わない（Hub `AUTHC-10`）。
- 実物との差・判定しないもの:
  - **要求の認証をしない**（共有値・署名の検証が無い）。この repo の spec に定めが無く、Hub `AEVT-26` 側にある。
    偽の生存確認で分断が隠れうるため、実物の合格の根拠にしない。
  - HTTP の表現（`x-db` 等）を持たない。型付きの入力で受ける（Hub `AEVT-26` が担当で検討中）。
  - 送出側の間隔・公表値（Hub `AEVT-24`）を受けない。送出・受信・監視は Hub の `AEVT-23`〜`AEVT-26` に移管済みで、
    本体に残るのは状態の観測の契約（`RVPG-62`）だけ（`A-2026-10-31-3`）。
- 書き手の読み:
  - 経過がちょうど閾値なら生存、超えたら非生存（Hub `AUTHC-21` の「超」の読み）。
  - 未受信は生存と数えない。時計の巻き戻りは安全側で非生存にする。秒未満の閾値は切り上げる。
  - 受信時刻が直前より後退する受信は記録に残すが、最終受信時刻は巻き戻さない。

### 3.6 JWKS の取得（`jwks::HubJwksEndpoint`・`jwks::AuthJwksFetcher`、#65）

- stub がすること:
  - `HubJwksEndpoint`: `fandhe-auth` が Hub の JWKS を取得する相手を模し、中間キャッシュの上限を模す
    （`OCL-31`〜`OCL-37`・Hub `D-2026-10-22-1`）。
  - `AuthJwksFetcher`: Hub が `fandhe-auth` の JWKS を取得して鍵の集合を保つ側を模す。保持の上限を超えたら
    鍵を返さない（fail-closed。`SIGN-39`・`SIGN-45`・`SIGN-47`、Hub `D-2026-10-20-2`・Hub `D-2026-10-16-17`）。
- 実物との差・判定しないもの: `jwks_uri` を参照も取得もしない。出す `alg` は ES256 に固定。JWKS に出すのは
  公開の欄だけで、秘密鍵の欄は型として持たない。
- 書き手の読み:
  - 2 方向の流れがあるという整理自体が書き手の読みで、人の確認を待つ。
  - 経過がちょうど上限ならまだ保持する。秒未満の上限は秒へ切り上げる。
  - 時計の巻き戻りでは古い本文を返さず、origin を取り直す。
  - `max-age` は整数の秒で、端数は切り捨てる。
  - 同じ `kid` を重ねて載せられる（`OCL-35` の作り分け用）。

### 3.7 障害注入（`fault::HubFaultInjector`、#66）

- stub がすること: 応答の遅れと拒否を注入する。対象は Hub の JWKS の配信、失効の通知の受け口、
  本人トークンの提示の受け口、生存確認の受け口。TASK-13 のハーネスが使う。
- 実物との差・判定しないもの:
  - 対象外の口は `assertion::AuthPort`・`feed::ChangeFeedPort`・`jwks::AuthJwksPort`（`fandhe-auth` 側の応答で、
    Hub の stub の応答ではない）。
  - 遅れは `Wait` のフックへ渡すだけで、実際に待たない。遅れの値は仮で、数値の根拠にしない
    （`THRT-29`・`A-2026-10-28-1`）。
  - 注入で成功を作る経路を持たない（`AVLB-18`・`AVLB-22`・`DPOL-30`）。
- 書き手の読み:
  - 拒否を HTTP の状態コード・接続の失敗で表すのは仮定である。
  - `MalformedBody` の応答の形（状態・`max-age`・`age`・キャッシュ由来の別・版）は仮に置いた。
  - 内側が適用した後で応答だけを失う形は作らない。実物で起きうる「適用済みだが応答が届かない」は stub で再現できない。

## 4. 設定の欄と所有者の ID

`HubStubConfig` の全欄は `StubValue` で「仮置き」の印を持つ。ここには値の列を作らない。

| 欄 | 用途 | 引く ID |
| --- | --- | --- |
| `client_id` | Hub が `fandhe-auth` を呼ぶときの `client_id`（assertion の `iss`・`sub`） | `OCL-24`・`OCL-42`、Hub `D-2026-10-22-2` |
| `public_host` | Hub の公開ホスト | `A-2026-10-28-1`、Hub `TASK-527` |
| `jwks_uri` | `jwks_uri` の URL（取得しない） | `OCL-31`・`TASK-310` |
| `logout_receiver_uri` | Logout Token の受け口の URL | `OCL-42` |
| `jwks_max_age` | JWKS の `max-age` | Hub `D-2026-10-20-2`・Hub `D-2026-10-22-1`・`SIGN-47` |
| `jwks_fetch_min_interval` | JWKS の取得間隔の下限 | Hub `D-2026-10-20-2`・`SIGN-47` |
| `jwks_cache_max` | 中間キャッシュの上限 C_max | Hub `D-2026-10-22-1`・`OCL-37` |
| `jwks_stale_max` | 最後に取得できた鍵の集合を使い続ける上限 U（欄の名前は仮置き） | Hub `D-2026-10-16-17`・Hub `D-2026-10-20-2`・`SIGN-39` |
| `assertion_max_lifetime` | assertion の有効期限の上限 | `OCL-25`・Hub `AUTHC-39` |
| `feed_fetch_min_interval` | 変更のフィードを読む間隔の下限（spec 上は未決） | Hub `AUTHC-35` |
| `heartbeat_loss_threshold` | 生存確認の途絶と見なす閾値 | Hub `AUTHC-21`・Hub `AUTHC-37`・Hub `D-2026-10-16-11` |

値の範囲の検査は本体側の設定の検証（`OCL-31`・`SIGN-47`）の担当で、stub は持たない。
