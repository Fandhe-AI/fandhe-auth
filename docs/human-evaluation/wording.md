## 準備（人）

1. `TASK-126` の基準が決まって記録されているかを確かめる。決まっていなければ止める（値は未定）。
2. 評価する画面と版（commit）を決めて控える。
3. 観察者と進行役を決める（どちらも人）。
4. 参加者を集める（人数は基準に従う）。参加者には番号を振り、個人情報は記録に書かない。
5. 観察の目的と記録の扱いを参加者に説明する。
6. 環境は検証用のものを使い、本番の秘密値・実機の名前を記録に出さない。

## 観察の手順

課題ごとに同じ順で行う。

1. 課題を口頭か紙で示す（例: ログインする、passkey を追加・削除する、認証セッションを失効させる、再ログインになる場面、承認画面で承認・拒否する、招待・復旧を進める）。課題の文は対象の文言をなぞらない。
2. 参加者が操作する。観察者は口を挟まない。思ったことを話してもらう形（発話思考）を使うかは観察者が決める。
3. 迷った箇所、誤った操作とその件数、読み違えた語を記録する。`DVUI-26`（→ Hub `ASCR-40`）の「端末」の読み違いの観点も見る。
4. 課題の後に短い聞き取りをする（どの文言で迷ったか）。
5. `IRUI-31`（→ Hub `ASCR-78`）の復旧コードを保管できるかの受容性は、別の課題として観察する。本物の復旧コードは使わず検証用の値を使い、値を記録に写さない。

記録の項目と照合欄の様式は 4/4（#3928）で作る。ここでは、どの手順で何を観察するかまでを定める。

## 人が行う旨

観察・評価・記入・判定・修正の判断は人が行い、AI・自動処理（LLM の要約による判定を含む）に代えない（`D-2026-10-17-51` の (1)、`ACPT-7`）。
AI が書いてよいのは手順書と空の様式までである。評価の結果で行のステータスを確定に変えるのは、人の記録による（`ACPT-7`）。
