## 注記: AI の結果を判定欄に入れない

- 判定・日付・判定者の各欄には **人だけ** が記入する。AI・自動処理による記入は 0 件にする（`TASK-83`・ACPT-7）。
- QP-1 の T 表の「判定」列・4 節の「推奨」、`security-auditor`・ai-review など AI のレビューの結果は参考の資料である。
  判定欄に写さない（CG-2・`D-2026-10-15-20`・`D-2026-10-16-21` の (1)）。
- AI のレビューの合格だけを安全性の根拠として記録しない（`ACPT-12` の期待。該当件数は 0）。備考欄にも書かない。
- 本様式は AI が作ったものであり、判定ではない。表の判定・日付・判定者は空欄で渡す。
- 一人で兼ねるため職務の分離が成り立たない限界は既知である（`D-2026-10-27-5`）。

## 記入のしかた

- 判定は「確認済み」「指摘あり」「未対応」のどれか 1 つを書く（`ACPT-12` の操作）。語の定義は、QP-1 の README が引く固定済みの記録の 3 節と 5 節にある。
  [review-material.md](review-material.md) の「レビューの準備と読む順」から辿り、様式では言い換えない。
- 日付は `YYYY-MM-DD` で書く。
- 判定者の書き方と、記入済みの記録票をこの public repo に置くかどうかは利用者が決める（未定）。様式には名前の例を書かない。
- 脅威の名前・指摘の本文・PoC の数値は書かない。指摘は番号で引き、本文は spec 側の記録に置く。
- 区分は [scope-ids.md](scope-ids.md) のラベルだけを写す。候補の行は、対応 ID の採否を人が書く（`ACPT-12` の「ほかの行の対応 ID は担当者が選ぶ」）。
