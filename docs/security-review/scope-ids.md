## 注記

- ステータスは上の commit 時点の写しである。spec 側の変更で古くなるため、`TASK-83` の着手時に原文で確かめ直す。
  ステータスの「確定／検討中」は spec 上の語であり、AI の判断の強さではない（ACPT-7）。
- `ACPT-12` の区分では、`ADLG-26`（R-1）は「持ち越しで連動」である（窓の上限の数値は測って決める持ち越し。`D-2026-10-17-2`・
  `D-2026-10-17-84`）。表のステータス欄の値とは別に、原文の区分を確かめる。
- `AGCR-29`（DPoP の検証部）は、`ACPT-12` が R の行と別に挙げている。根拠欄は QP-1 の R の表と PoC-9 を引くが、
  特定の T・R の行には結び付けていないため、別枠に置いた。
- 候補の行は、根拠欄が QP-1 の `T-N` や PoC の手順を引く項目から、「未確認の残り」に当たるものを選んだ。
  原文指定の 3 行（T-6・T-10・T-16）より広く拾っている場合がある。広すぎる・足りないと判断した場合は、
  `TASK-83` の担当者が ID を足し引きする。
- R-5・R-6 は、`ACPT-12` の期待で、ビヘイビアへの反映（P4）が済んでいることの確認が要る（`SIGN-49`・`SIGN-50`・`OPRV-8`）。
  この確認は `TASK-83` で人が行う。
