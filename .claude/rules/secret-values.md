# 秘密値の扱い（コーディング規約）

正本は `docs/spec/04-behavior/secret-handling.md`（SECR）。多くは「検討中」だが守る規則として扱う。
ここに無い判断（値の種類の追加・例外）は原文を確かめ、決まっていなければ利用者に伺う。

## 秘密値の型は 1 つ

- 秘密値の型の実装は `fandhe-auth-secret`（`crates/secret`）に 1 つだけ置く（SECR-31・SECR-15）。
  PoC の 3 実装（PoC-1・PoC-11 の `Secret`、Hub の複製の `Token`）を写さない。新しい秘密値の型を別 crate に作らない。
- `fandhe-auth-secret` は HTTP・DB・非同期ランタイムに依存しない小さな crate にする（DPOL-41）。
- 秘密値を持つ全ての型（設定の型・入れ物の型・試験の入れ物を含む）が対象（SECR-10・SECR-29）。生の `String`・`Vec<u8>`・`[u8; N]` の
  フィールドに秘密値を持たせず、専用の秘密値の型で包む（SECR-30・SECR-21・SECR-33）。
- 対象の型の一覧（SECR-10・SECR-29）を保つ。CI の構文木の走査で秘密値らしい欄を持つ型を見つけ、その型が一覧に無い、または欄が
  専用の秘密値の型でなければ CI を失敗させる（SECR-21。検討中。道具は TASK-4 で選ぶ）。走査は人のコードレビューの確認項目で補う（SECR-21）。
- 型を足す変更で、一覧と試験の片方だけを更新したものも CI を失敗させる（SECR-32。検討中）。

## 出力（Debug・Display・Serialize）

- `{:?}`・`{:#?}` は固定の文字列だけを出す。値・値の一部・長さ（`len=N` も不可）・ハッシュを含めない（SECR-11）。
- `Display` は実装しないか、`Debug` と同じ固定の文字列にする（SECR-12）。
- 秘密値を持つ構造体に `#[derive(Debug)]` を付けても値が出ないことを試験で確かめる（SECR-13・SECR-30）。
  `Debug` を付けていないから出ないだけの状態に頼らない（SECR-21 の根拠）。
- `Serialize` は値を出さないか、実装しない。外から受け取る値の `Deserialize` は妨げない（SECR-17。検討中）。

## 取り出し

- 値の取り出しは `expose()` のような明示の名前のメソッドだけ（SECR-16）。
- 暗黙の型変換・`Deref`・`AsRef<str>`・`From<Secret> for String`・公開フィールドで取り出せる経路を作らない（SECR-16）。
- 呼び出し箇所の一覧を CI で作り、一覧の変更には人のレビューの承認を要する（SECR-16。検討中。メソッド名と形は実装の段階で決める）。
  取り出しは、ハッシュ化・署名・外への送信の直前に限る（spec の ID が無い推奨。SECR-16 はこれらの用途で取り出す箇所を前提にする）。
- `zeroize` 相当は Could（SECR-22）。入れるなら共有の型 1 つに持たせる。

## 置き場所

- 秘密値を持つ型は公開の crate に置き、外から名前を指して試験を掛けられるようにする（SECR-19・SECR-33）。
- 非公開の型・bin crate の中の型に秘密値を持たせない。持たせるなら専用の秘密値の型で包む（SECR-33）。

## 保存の形

| 値 | 保存の形 | 根拠 |
| --- | --- | --- |
| 128 ビット以上の値（セッション値・refresh・認可コード・デバイスコード・招待トークン・復旧コードの秘密部） | 鍵なし SHA-256 | SECR-1・SECR-2・SECR-4・SECR-7・SECR-34 |
| ユーザーコード・確認コード（低エントロピー） | HMAC。鍵は認証 DB と別の保管先（SECR-9） | SECR-7・SECR-34 |
| client secret（採る場合。OCL-18・OCL-19） | `argon2` のハッシュ | SECR-8（検討中） |
| 署名鍵 | KEK で包んだ形 | SECR-5 |
| KEK・DB パスワード | 認証 DB の表に入れない | SECR-6 |

- 平文・可逆な形で保存する列を作らない。復旧コードは 1 コード 1 行（SECR-3）。
- 暗号・ハッシュは既存の crate を使い、自前で実装しない（DPOL-4・DPOL-47。`.claude/rules/dependency-policy.md`）。
- 秘密の保管先の具体の構成は持ち越し（SECR-9）。決まるまで保管先を推測で固定しない。

## 出してはいけない場所

次の場所に秘密値（JWT の形の文字列を含む）が出る件数を 0 にする（SECR-23〜27・AAUD-30）。

- ログ・誤りの応答・監査の記録・DB のダンプ・バックアップ・結果のファイル・stub の記録・console のコーパス（SECR-23・SECR-24・SECR-26・SECR-27・AAUD-30）
- 前段のリバースプロキシのアクセスログ・URL のクエリ・転送先のログ・エラーページ（SECR-25。検討中。出る場合は `POST`・ヘッダ・
  一度だけの短期限の経路か、前段のログの除外設定で防ぐ）

走査は生・base64・base64url・16 進の形でも一致を探す（AAUD-30）。

次は spec の ID が無い補足（守る規則として扱う）。

- 誤り型のメッセージ・`panic!`・`expect()` のメッセージ・構造化ログのフィールドにも出さない（ログの部品は TASK-4 で選ぶ）。
- 新しい出力先を足したら走査の対象に加える。
- Git・サンプル・試験の記録・フィクスチャへの混入防止は `.claude/rules/security.md`（05-tasks.md の方針）に従う。試験は実行時に
  生成した値を使い、コミットしない。
