# 日本語スタイル規約

## 基本方針

ユーザーへの説明・報告、Agent・Rule の本文、PR / Issue の本文、コード内コメントは**日本語**で書く。
コード・コマンド・識別子は英語のまま維持し、翻訳しない。

## 言語の使い分け

| 要素 | 言語 |
| --- | --- |
| ユーザーへの説明・報告・確認 | 日本語 |
| コード・コマンド・識別子（crate 名・型名・関数名・ファイル名・feature 名） | 英語のまま |
| spec ID・決定 ID（`SECR-11`・`D-2026-10-29-1`・`TASK-3`） | 原文のまま |
| コミットメッセージの要約・本文 | 日本語可（type・scope は英語。`./conventional-commits.md`） |
| PR タイトル・Issue タイトル | 日本語可（Conventional Commits の type・scope は英語） |
| PR / Issue の本文 | 日本語 |
| コード内コメント・rustdoc | 日本語を基本とする（`./code-comment-style.md`） |
| YAML frontmatter の値 | 日本語可（キー名は英語） |
| `scripts/*.sh` の実行時出力（`log`・エラー・usage） | 英語（`./makefile.md`。既存スクリプトに合わせる） |

Rust のログ・誤り応答の文言の言語は、構造化ログの部品とあわせて未定（TASK-4 で決める）。
外に返す誤り応答の形は spec の ID（THRT-1・CSRF-1・AVLB-22 等）に従い、ここで文言を決めない。

例:

```
feat(secret): 秘密値の型の雛形を追加
```

```bash
# コマンド・引数は英語のまま
gh pr create --title "feat(secret): 秘密値の型の雛形を追加"
```

## トーン

- **常体（だ・である調）** を基本とする
- ユーザーへの案内・確認は常体で簡潔に書く
- レポート・一覧は常体。判定は事実（実行したコマンド・出力・spec ID）を添えて書く
- 丁寧語（「ください」「します」）は必要最小限に留める
- spec の「確定／検討中」は spec 上のステータスの語として使い、AI の判断の強さを表す語として流用しない（ACPT-7）

## 禁止事項

- 日本語の問いかけに英語のみで返答しない
- コード・コマンド・識別子を日本語に翻訳しない
- 他所有者（Hub・fandhe-backend・fandhe-frontend・fandhe-db）の値や本文を写さない。ID で引く（`./spec-reference.md`）
- 秘密値（`./secret-values.md`）・実機の名前・ホームのパス・内部のアドレスを本文・例に書かない
- 絵文字の多用（レポートの判定記号 ✅ / ⚠️ / ❌ は許可）
